## 审查入口

工作区内打开 `概念图/2026-10-26_从零建模_V04/index.html`。每件包含原概念、正/侧/背/顶/透视截图，以及含菜单、工程名称和部件大纲的完整编辑器截图。四套防具额外提供与原概念轻微透视接近的参考角度，明确区别于严格三视图。

用户已确认评分口径：轮廓与比例40分、部件结构30分、配色15分、细节15分；每件需达到95分，由用户最终确认。审查页支持填写评分、意见并导出JSON，初始不预填分数，不自动宣称通过。

## 制作方式与范围

- 规则构件使用原生Cube；刀刃、握柄、护手、肩甲等斜面使用原生Mesh/MeshFace闭合多边形挤出，可独立编辑。
- 贴图重新从V01原始概念的正/侧/背或顶视投影采样，并补绘端面材料色块；包含概念原图的绘制光照，不是独立手绘的游戏UV贴图。
- 防具保留概念比例和展示内衬；当前没有绑定Minecraft骨骼。武器为自由模型格式，尚未做Java物品格式转换或最终游戏优化。
- 本轮未替换生产资源、物品图标、安装目录或JAR；审查工程不能直接当作安装包使用。
- 武器没有完整反侧专图，采用对称结构补全；严格正交图与原图轻微透视不可能逐像素一致。局部厚度和背向细节仍需审美确认。

## 证据与可回溯性

- `validation.json`：所有模型SHA-256、闭合性检查、截图哈希。
- `reference-bounds.json`、`reference-masks/`：从原始概念独立提取的参考轮廓；算法会填补不透明表面的暗色区域并保留标注的真实开口。
- `silhouette-review.json`：原生截图与参考轮廓的IoU。防具统一高度、武器统一长度后居中，保持宽高比例；**这个二维指标不等于综合匹配度**。背景色提取可能受暗色阴影、细线和透视影响，应结合差异图判断。
- 审查目录各装备的`construction.json`、`receipt.json`、各方向`*-camera.json`记录原图坐标、工具版本、原生重开数量和相机参数。
- 审查目录`iterations/`保留后续修订前的模型、截图和回执；过程失败与修复详见仓库`process.md`的Z01–Z10、L066及后续条目。

## 重建与验证

本地Blockbench需开启仅localhost的9228调试端口。下列脚本通过本地接口调用真正运行的编辑器：

```text
python scripts/concept_reference_bounds.py
python scripts/concept_rebuild.py
python scripts/validate_concept_rebuild.py
python scripts/concept_review.py
```

`concept_rebuild.py --ids coil_pistol`可单独重建一件，会归档该件当前工程与证据。它是显式制作命令，不属于正常模组构建流程；人工修改工程后不要误运行重建覆盖修改。
