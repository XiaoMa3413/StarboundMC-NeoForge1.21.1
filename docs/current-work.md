## 太空渲染

- 跨 GPU/驱动、低端显卡、shaderpack，以及完整相机运动、极端视角和不同 FOV 的时间稳定性。固定视点或单点 GPU 通量检查不能替代这些验收。
- 近地表的 4K 资产/网格/薄云壳、相交透明体积、艺术化单次散射与长存档 float 动画精度仍有限制；测试方法见[开发指南](development/space-render-testing.md)。
- 黑洞为独立原型方向：先建立任意方向/角足迹的恒星背景查询和 Schwarzschild 数值基准，再讨论吸积盘、Kerr 与美术目标。

## 仓库与开发资产

- `docs/models/` 是暂存开发美术资产，保持原位且不属于默认架构阅读。Gradle 不直接消费它，7 个生产资源导出工具及手工流程引用该路径。未来 `docs/models → dev-assets` 迁移须同时更新工具、链接、输出约定与人工流程，并重新验证资源；大量 validation PNG 的长期 Git 策略单独决定。
- client/network 采用 touch-to-migrate：实质修改 feature 时，相关类向现有 feature package 收敛；不做数百文件 package-only 搬迁或新增迁移 adapter。
- 两套星图均有当前设备/菜单入口，见[导航 reference](reference/universe.md)。是否长期保留两种 UI，需实际使用和产品判断后独立处理，不能仅凭实现新旧删除。
