## 1. 设计出发点

玩家通过个人装备观察、行动和生存。世界占据视觉中心，HUD 在边缘回答三个问题：自身是否安全、正在操作什么、接下来去哪里。左下承载 N.O.V.A. 通讯，右下承载生存读数。

参照 NMS 的分区与情境呈现，以 StarboundMC 实际存在的数据和操作为内容。全套 HUD 采用同一套信息语法；不照搬 NMS 的生命支持消耗规则、护盾机制、工具热量或通缉等级。

## 2. Design Contract

- **SCREEN**：StarboundMC 通用玩家 HUD，覆盖步行、探索、EVA、危险环境和系统连接。
- **PURPOSE**：在不中断观察与操作的情况下识别风险、状态、目标和下一步行动。
- **INTERACTION FANTASY**：个人视觉设备提供必要的生存与探索辅助。
- **SCREEN MODE**：Experience。
- **PRIMARY VISUAL**：世界与当前交互对象。风险升级时，对应状态取得最高 HUD 注意优先级。
- **INFORMATION PRIORITY**：迫近的生命危险 → 当前交互反馈 → 当前导航/行动 → 资源状态 → 一般系统通知。
- **INTERACTION FLOW**：事件或状态触发 → 固定语义区域出现信息 → 行动/状态变化 → 有意义的反馈 → 收起。详细信息留给相应界面。
- **SPATIAL ORGANIZATION**：左下 N.O.V.A. 通讯、右下生存信息为固定约束；顶部方向与当前装备，中央只保留准星与聚焦对象。基础生命/护甲及一般行动提示的位置继续讨论。
- **ART / CUSTOM VISUALS**：图标、短横条、清晰文字、局部底衬、少量强调色；移除统一曲面和泛滥的发光。
- **GENERIC UI**：文本、状态条和按键提示；不采用常驻多卡片仪表盘。
- **MOTION / FEEDBACK**：出现、更新、警告、完成均表达实际状态。平面文字保持稳定；光学跟随与环境覆盖效果独立，可后续再定强度。
- **STATES**：安静探索、导航、操作工具、生存危险、资源恢复、EVA、启动/连接、通讯。
- **DO NOT**：为每个系统加一块独立 HUD；重复显示原版状态；把所有读数染青色；常驻整屏刻度；持续漂移或扫描；将新任务/扫描器功能混入视觉重构。
- **IMPLEMENTATION CONTRACT**：可以重排现有 HUD，并规划原版生命/护甲等信息的统一呈现。必须保持真实数据、游戏规则、H5 服务端权威和个人进度；World AR 始终锁定世界，N.O.V.A. 通讯保持独立平面。没有数据的区域保持空白。

## 3. 屏幕分区草案

| 区域 | 回答的问题 | StarboundMC 内容 | 与当前版本的差异 |
| --- | --- | --- | --- |
| 左上 | 我是否受伤、还能承受多少伤害？ | 生命、实际护甲/吸收状态；受伤时突出 | 将原版对应读数纳入统一设计，避免与新 HUD 重复 |
| 顶部中央 | 我面朝哪里，目标在哪个方向？ | 简化 Compass、已知目标方向 | 降低连续数字刻度密度，以方向与目标图标为主 |
| 右上 | 我手里是什么、处于什么模式？ | 当前工具及已有真实模式/资源数据 | 不把系统日志永久占在这里；无适用工具时留空 |
| 左下（已确定） | N.O.V.A. 正在告诉我什么？ | N.O.V.A. 肖像与通讯正文 | 保留现有位置与肖像身份，统一文字层级和进出反馈 |
| 右下（已确定） | 环境对我有什么影响，资源能否支撑？ | 当前环境、O₂、Cold/Heat、饥饿等必要资源信息 | 保留生存信息所在区域，按同组横条组织，不再各自居中堆叠 |
| 中央 | 我正在瞄准/接近/操作什么？ | 准星、聚焦对象的 AR 信息、交互提示 | 非聚焦目标优先压成图标，靠近或聚焦后展开详情 |
| 底部中央 | 我如何切换当前物品？ | Minecraft 九槽快捷操作 | 保留现有操作语义，视觉作为统一 HUD 的独立适配项 |

这是对 NMS 分区理念的项目映射。Minecraft 的护甲不显示成可充能护盾，冷热暴露不伪装成不存在的防护电量。各读数的语义必须让玩家能判断正确行动。

全局采用统一安全边距。小 GUI 视口下优先缩短/换行辅助文本，再收起次要信息，不整体压小关键读数。左下通讯、右下生存读数均避开快捷栏；原版聊天、字幕、计分板等需要在布局验收时检查冲突。

一般操作提示与未来任务摘要的位置尚未确定，不挤入右下生存组。当前交互提示优先靠近聚焦对象；N.O.V.A. 的任务说明仍通过左下通讯表达，H6 之前不新增任务摘要区域。

## 4. 显示规则

| 情境 | 保留的信息 | 需要强调的变化 |
| --- | --- | --- |
| 安全探索、无目标 | 最低限度基础状态与当前操作 | 环境名称进入区域时短显；不常驻完整仪表 |
| 正在导航 | Compass、当前目标图标/距离 | 聚焦或接近目标时展开标签，远处不常驻大段文字 |
| 真空/EVA | O₂、飞船方向、当前推进/操作状态 | 氧气下降按现有阈值升级；操作提示放到行动区 |
| 冷热危险 | 当前危险图标与暴露条，必要氧气读数 | 最高危险排在生存组首位；升级时短促强调，避免反复换位 |
| 返回安全区/补给 | 恢复中的相关读数 | 显示恢复，再在状态稳定后淡出 |
| 使用工具 | 当前工具真实模式与必要资源 | 开始使用/切换模式时显示；无数据则不虚构仪表 |
| NOVA 通讯 | 左下肖像与通讯正文 | 按队列逐条呈现；右下生存读数同时保持可见 |
| H5 启动/连接 | 临时系统反馈、必要生存警告 | 保持已完成的启动时序；完成后释放位置，不留下常驻系统控制台 |

“稳定分区”和“按需出现”同时成立：位置表达信息类别，出现与否表达当前是否相关。

基础生命危险不能被 HUD 尚未启动、普通通讯或菜单恢复动画掩盖。原版信息迁移时必须有完整替代，再关闭旧显示。

## 5. 视觉语法

- **主文字**：清晰的白/冷白，保证在明亮和复杂地形上可读；不再把所有文字作为青色发光纹理。
- **次要文字**：降低明度，减少词数；优先靠对齐和间距区分层级。
- **颜色**：青色用于导航与数字交互，琥珀用于资源压力与预警，红色用于真实危险，绿色用于恢复/完成。颜色必须配合图标或文案。
- **资源**：在右下统一左图标、横向状态条、必要数值的语法；同类条保持一致宽度和阅读方向。
- **结构**：用留白、细线、必要的半透明底衬保证读数，不给所有信息套框。
- **光学**：平面、稳定、无屏幕边缘压缩。普通文字不依赖 Glow 建立科技感；强调光只服务于状态或焦点。
- **运动**：先做好信息的进入、更新和退出，再评估是否需要微弱惯性；不预设所有组件共享同一漂移、同一光晕强度。
- **环境效果**：结霜/热扰动属于状态驱动的独立屏幕层，与文字分离；此轮不新增相关玩法或效果。

## 6. 提示协调

同一区域同一时刻只保留一个主要信息。

- 左下按“紧急通讯 → 普通通讯”的优先级逐条呈现，同一时刻只有一条主要通讯。
- 右下按当前生存风险组织读数；N.O.V.A. 通讯不能覆盖或挤走生存警告。
- 世界 AR 只显示已知信息；当前目标优先，其他目标收成低干扰图标。
- 短期进度与完成反馈在原位置更新，避免每个结果都弹出新窗口。
- 一般提示不占用右下生存位置。在 H6 之前使用现有通讯与情境数据，不实现任务提供器。

## 7. 后续实施拆分

1. 用安全探索、EVA、冷热危险、NOVA 通讯四种状态校准整体布局与字体/颜色；先确定完整视觉。
2. 按确认后的方案统一基础状态、右下生存组、Compass、工具信息与左下通讯的呈现规则，按真实数据逐项接入。每迁移一组再关闭对应旧显示。
3. 适配 H5 启动与连接反馈、窄视口和原版界面避让。
4. 最后微调动效与局部光学，做中英文、GUI Scale 2/3/4 实机验收。

上述均为 HUD 呈现工作。新任务、Scanner、Space POI 和其他 H6 功能不随本方案自动开工。
