# StarboundMC 当前系统手册

> 最后按代码审计：2026-08-23
> 适用版本：`0.1-alpha` / Minecraft Forge 1.20.1

本文面向维护者，描述当前分支已经实现的玩法、代码边界、持久化所有权和验证方法。
项目入口与构建命令见 [`README.md`](../README.md)；四份 `*-plan.md` 是历史方案与阶段验收记录，
不代替本文的当前实现说明。

## 1. 当前玩法闭环

1. 玩家首次登录时获得物质枪和传送器，并被送入飞船维度。
2. 玩家在紧凑初始飞船内使用工作台、燃料控制器、传送器和驾驶台。
3. 驾驶台打开三级星图，选择可达天体并消耗燃料启动固定航线。
4. 服务器推进连续宇宙中的飞船位置与姿态；客户端同步渲染星体、环境和跃迁演出。
5. 到达后，玩家通过传送器进入当前行星表面，采集或探索后返回飞船。
6. 物质枪组件可用于升级采集速度、射程、挖掘等级和时运。

### 当前内容边界

| 内容 | 当前状态 |
| --- | --- |
| 恒星系 | `sys1`、`sys2` 两个静态定义 |
| 可达天体 | 翠绿、熔岩、冰冻、荒芜 |
| 锁定占位 | 气态巨行星、岩石卫星 |
| 飞船控制 | 服务器权威固定航线；尚无玩家自由驾驶 |
| 行星表面 | 熔岩、冰冻、荒芜为独立维度；翠绿使用主世界占位 |
| 矿物来源 | 方块、物品与配方已实现；世界生成未开启 |

## 3. 初始飞船

### 3.1 程序化船体

相关代码：

- `world/StarterShipHullProfile.java`：不依赖 Minecraft 类的纯几何截面。
- `world/ShipStructure.java`：方块材质、设备布局和方块实体创建。
- `world/ShipChunkGenerator.java`：在对应区块调用船体放置。

船体指向 `+Z`，整体包围盒为：

| 轴 | 范围 | 尺寸 |
| --- | ---: | ---: |
| X | `-6..6` | 13 |
| Y | `99..106` | 8 |
| Z | `-9..11` | 21 |

主要构成：

- 逐截面收束的中央船体，而不是三间矩形长舱。
- 舰尾中央推进器面与两侧短引擎吊舱。
- 单层共用舱、一道 2 格高自动工程气闸和 5 格宽抬高驾驶台。
- 低矮深色玻璃驾驶舱罩、阶梯式舰首、短龙骨。
- 传送器、四个储物仓、工作台、合金炉、燃料控制器、双驾驶台和船长椅。

飞船传送器位于 `(0,101,0)`，玩家落点和默认飞船位置为 `(0,102,0)`。

`ProtoChunk.setBlockState` 不会自动创建方块实体，所以 `ShipStructure.place()` 必须显式创建
气闸门、储物仓和合金炉的 BlockEntity。修改这一流程时必须实测门的 tick 与容器持久化。

### 3.2 自建结构覆盖

`ShipTemplatePlacer` 会尝试加载 `data/starboundmc/structures/ship.nbt`。模板存在且本存档尚未
放置时，会以 `(0,102,0)` 为模板原点覆盖程序化飞船；模板不存在时继续使用默认探索艇。

建议工作流：

1. 备份并重建测试世界的飞船维度。
2. 用结构方块保存 `starboundmc:ship`。
3. 将生成的 NBT 放到 `src/main/resources/data/starboundmc/structures/ship.nbt`。
4. 再次重建飞船维度验证原点、方块实体和落点。

实体不会随结构模板保存；储物仓等方块实体数据可以随模板保留。

## 4. 星图、连续空间与固定航线

### 4.1 星图数据模型

`StarSystems` 与 `Planet` 枚举解耦：

- `Planet` 表示已经接入的四个实际目的地。
- `PlanetEntry.destination == null` 表示仅在星图展示、不可跃迁的占位天体。
- `parentEntryId` 表示卫星与主行星的关系。
- `StarmapBodyVisual` 定义贴图、颜色、表面细节、大气和环等视觉数据。
- `StellarVisualProfile` 定义恒星的宇宙位置、距离响应、颜色和特效权重。

新增内容时，至少需要同步检查静态定义、翻译键、目的地维度、天体贴图、停泊位置和自动测试。

### 4.2 三级星图交互

星图使用接近全屏的响应式布局；低逻辑分辨率时，详情区变为可关闭抽屉。几何和控件可在
物理像素足够时使用 2× 绘制密度，正文仍使用 Minecraft 原生字体。

当前三级页面：

1. **星域页 `GALAXY`**：展示每个恒星系；首次点击选择并显示详情，再次点击同一恒星或使用
   “进入恒星系”进入系统页。
2. **恒星系页 `SYSTEM`**：恒星和主行星可交互；卫星只作为所属主行星附近的缩略图展示，
   不能在总览页直接选择。
3. **行星聚焦页 `BODY_FOCUS`**：放大主行星并显示直属卫星及轨道；主行星与直属卫星均可选为
   详情或跃迁目标。

补充规则：

- 再次点击同一主行星进入聚焦页；返回按钮或右键逐级后退。
- 宽屏详情固定在右侧；紧凑抽屉打开时，点击地图空白处可关闭。
- 页面、恒星系、聚焦主体和选择在同一客户端会话内记忆，重开星图后恢复。
- 跃迁中锁定手动切页和天体交互，跨星系时页面按空间影响自动切换为出发系统、深空和到达系统。
- 详情采用单页分段信息卡，不显示辐射值、环境值，也没有类别切换按钮。

星图视觉方案与阶段验收见：

- [`starmap-high-density-ui-plan.md`](starmap-high-density-ui-plan.md)
- [`starmap-art-direction-plan.md`](starmap-art-direction-plan.md)

### 4.3 连续宇宙

`UniversePosition` 使用 `SectorCoordinate(long x,y,z)` 加局部坐标：

- 每个分区边长 `100,000`。
- 局部坐标规范化到约 `[-50,000, 50,000)`。
- 差值运算先计算分区差，再叠加局部差；不会先构造巨大绝对 float。
- 当前两个恒星系仍位于零号分区，格式已经支持未来跨分区扩展。

`GalaxySpatialIndex` 按分区保存静态恒星系；`StarSystemResolver` 只解析附近候选以及当前/目标
导航提示。恒星渲染按屏幕投影大小和星系影响分为完整、简化、星点三级，预算上限为 3 颗完整
恒星与 16 颗简化恒星，其余进入批量星点路径。相邻 LOD 在约 18 tick 内交叉淡化。

星系环境由连续影响权重混合，用于天空轻微染色和未来音景接口；这些值不在星图 UI 中展示。
两个星系之间存在中性深空区，不会以字符串系统 ID 发生硬切换。

### 4.4 飞行阶段与燃料

物理船体和玩家仍固定在飞船维度；`ShipFlightController` 推进虚拟宇宙坐标与朝向。

阶段顺序：

```text
DOCKED → TURN → ACCELERATE → CRUISE 或 HYPERSPACE → DECELERATE → ARRIVE → DOCKED
```

- 短航线固定 `220 tick`，约 11 秒。
- 长航线按距离增长，最大 `560 tick`，约 28 秒。
- 同星系消耗 20 燃料，跨星系消耗 100，油箱上限 1000。
- 服务器生成确定性平滑航线，并使用天体安全半径绕开行星，不允许路线穿过星体。
- 航向跟随航线切线，pitch 表达加减速，roll 表达转弯侧倾。

`ShipWarpManager.WARP_TICKS` 只是旧调用兼容常量，不再代表所有跃迁的固定时长。

### 4.5 同步、恢复与渲染

服务端是飞行真值源：

1. `StartWarpPacket` 只携带星图条目 ID。
2. 服务端验证玩家维度、目标是否存在/可达、目标是否不同以及燃料是否足够。
3. 服务端扣除燃料、持久化飞行并广播开始提示和首个 `SyncFlightPacket`。
4. 飞行中每 5 tick 或阶段变化时广播位置、速度、姿态和进度快照。
5. 客户端在快照之间重采样同一条确定性曲线，避免网络间隔造成卡顿。
6. 抵达后服务端更新当前天体、当前条目和访问记录，再广播最终状态。

客户端连接状态含 revision；新服务器会重置 revision，避免重启后客户端拒绝从 0 开始的新快照。

飞船维度使用 `SkyType.NONE`，`PlanetRenderer` 负责：

- 2000 颗相机相对星空背景。
- 连续空间中的行星、恒星、昼夜面与大气辉光。
- 远景恒星星点、简化盘面和完整恒星的 LOD 过渡。
- 转向、加速、超空间星线、减速、到达淡入与闪光。

世界空间几何传给渲染器前必须转换成相机相对坐标。当前渲染帧中 `+Z` 是相机前方；将特效
画到负 Z 可能被近平面裁剪。这一约束同样适用于行星、激光和全屏空间特效。

飞行设计与连续空间实现记录见：

- [`ship-motion-warp-plan.md`](ship-motion-warp-plan.md)
- [`continuous-space-modular-plan.md`](continuous-space-modular-plan.md)

## 5. 燃料控制器

相关代码：`FuelControllerBlock`、`FuelControllerBlockEntity`、`FuelControllerMenu` 和
`FuelControllerScreen`。

- 五个持久燃料槽。
- 煤炭 10、木炭 5、烈焰粉 20。
- “添加燃料”会逐个消耗能完整装入油箱的燃料；装不下的剩余物保留在槽位。
- 所有容器修改必须走 `Container` API，并调用 `setChanged()`；菜单随后 `broadcastChanges()`。

旧存档中，在 FuelController 获得 BlockEntity 之前已经放置的方块可能没有实体。遇到无 UI 或
不保存时，应拆除并重新放置该方块。

## 6. 传送器网络

统一方块 ID 为 `starboundmc:teleporter`。旧的 `ship_teleporter_block`、`ship_return_portal` 和
`ship_teleporter` 由 `ModMissingMappings` 重映射。

目的地包括：

- 飞船传送器上方。
- 当前天体表面。
- 其他已经命名且仍然存在的传送器上方。

未命名传送器不会出现在共享列表中；方块被拆除后会注销，列表读取时也会剔除失效条目。
名称修改后通过网络刷新已打开的传送器 UI。

## 7. 物质枪

### 7.1 采集模型

物质枪只通过右键持续激光采集：

- 左键破坏速度被设为 0，并取消方块破坏事件；创造模式也不能用它左键秒拆。
- 基础射程 8 格，每级射程升级增加 2 格。
- 照射同一方块逐 tick 累积进度；松开、换目标或目标消失会清零。
- 进度由方块硬度、工具等级是否足够、速度升级共同决定。
- 等级不足时方块可被激光破坏但不会掉落。
- 掉落通过物质枪 ItemStack 手动调用资源表，因此真实时运附魔能够生效。

### 7.2 四轨升级

| 轨道 | 上限 | 效果 |
| --- | ---: | --- |
| 速度 | 3 | 每级乘 `1.5`，三级为 `3.375×` |
| 射程 | 3 | 每级 `+2` 格 |
| 挖掘等级 | 2 | 0：石镐等价；1：钻石镐等价；2：下界合金等价并可采远古残骸 |
| 时运 | 3 | 写入 `FortuneUpgrades`，并重建真实 `BLOCK_FORTUNE` 附魔 |

升级到第 1、2、3 级分别消耗 1、2、4 个物质枪组件。旧 `Upgrades` NBT 会迁移为速度轨；工作台
每次升级也会重建时运附魔列表，修复旧版本可能留下的重复附魔条目。

工作台 UI 为 176×250 的程序化像素工业面板，不依赖
`textures/gui/matter_manipulator_workbench.png` 完成主体绘制。

## 8. 资源与制造

当前材料链：

```text
原钨 → 钨锭
原钛 → 钛锭
原耐钢 → 耐钢锭
星核原矿 → 星核碎片
```

- 原钨和原钛使用原版熔炉，烹饪时间 200 tick。
- 原耐钢和星核原矿只能由钛制合金炉处理；星核需要 320 tick，其余为 200 tick。
- 8 个钛锭围绕 1 个原版熔炉合成钛制合金炉。
- 1 钛锭、2 星核碎片、1 耐钢锭和 1 红石合成 2 个物质枪组件。

四种矿石、原矿和成品已经注册并进入创造标签，但当前资源目录没有对应的 configured feature、
placed feature 或 biome modifier，因此生存世界不会自然生成这些矿脉。

## 9. 行星维度与天空

| 天体 | 维度 | 地形与天空 |
| --- | --- | --- |
| 翠绿 | `minecraft:overworld` 占位 | 使用主世界；熔岩卫星替代原版月亮显示 |
| 熔岩 | `starboundmc:molten` | 自定义开放式下界地表、熔岩湖、下界生物群系，无基岩天花板 |
| 冰冻 | `starboundmc:frozen` | 主世界噪声 + 寒冷群系过滤，自绘冷色天空和红矮星 |
| 荒芜 | `starboundmc:barren` | 主世界噪声 + 干燥群系过滤，地形生成水被移除或转为有支撑的沙床 |

### 熔岩维度

`MoltenChunkGenerator` 生成约 Y=12–96 的起伏表面，基准 48、振幅 26、熔岩面 32；底部
0–4 为基岩。地表材质根据下界群系选择下界岩、灵魂沙、菌岩、玄武岩或黑石。

熔岩天体被视为翠绿天体的卫星。主世界使用透明 `moon_phases.png` 隐藏原版月亮，再由
`MoltenMoonRenderer` 绘制带月相的熔岩球体。

原版下界入口被全局禁用：任何维度都不能点燃下界传送门，已有门也不能进入
`minecraft:the_nether`。这是当前玩法规则，不是临时渲染限制。

### 冰冻维度

`FilteredBiomeSource` 只保留雪原、冰刺、针叶林、冰封海洋、雪坡和冰峰等寒冷群系，其他采样
回退为雪原。`FrozenDimensionEffects` 关闭原版天空，`FrozenSkyRenderer` 绘制冷色天空盒和红矮星。

### 荒芜维度

允许沙漠、恶地、热带草原等干燥群系，其他采样回退为沙漠。`BarrenChunkGenerator` 在
`fillFromNoise` 后处理地形水：有支撑的水变为沙子，无支撑的含水层水团变为空气；后续结构
生成的水（例如沙漠水井）不在这一阶段内。

## 10. 输入与网络

### 快捷键

`H`：从任意维度请求返回飞船传送器上方。服务端通过 `TeleportToShipPacket` 执行传送。

### SimpleChannel

协议版本：`4`。注册顺序就是包 ID，不能在中间重排而不升级协议。

| ID | 包 | 方向 | 用途 |
| ---: | --- | --- | --- |
| 0 | `UpgradeMatterManipulatorPacket` | C→S | 四轨升级请求 |
| 1 | `StartWarpPacket` | C→S | 请求跃迁到星图条目 |
| 2 | `SyncStarStatePacket` | S→C | 访问记录与当前条目 |
| 3 | `SyncPlanetPacket` | S→C | 当前天体 |
| 4 | `WarpStartPacket` | S→C | 兼容开始提示、目标和总时长 |
| 5 | `SyncFuelPacket` | S→C | 油量与上限 |
| 6 | `TeleporterListPacket` | S→C | 传送器列表 |
| 7 | `TeleporterUsePacket` | C→S | 使用目的地 |
| 8 | `TeleporterRenamePacket` | C→S | 修改名称 |
| 9 | `TeleportToShipPacket` | C→S | 快捷键回船 |
| 10 | `AddFuelPacket` | C→S | 消耗燃料槽物品 |
| 11 | `SyncFlightPacket` | S→C | 分区坐标、速度、姿态、阶段与进度快照 |

所有 C→S handler 必须在网络线程之外 `enqueueWork`，并以服务器当前菜单、玩家维度和静态注册表
重新验证客户端输入。

## 11. 存档兼容与重置

| 变更 | 建议操作 |
| --- | --- |
| 程序化船体 | 退出世界后重建 `dimensions/starboundmc/ship` |
| 熔岩、冰冻、荒芜生成器 | 备份后重建对应 `dimensions/starboundmc/<id>` |
| 方块注册名 | 保留旧项或新增 `MissingMappingsEvent` 重映射 |
| 飞行坐标格式 | 保留旧绝对坐标字段读取；新格式写分区和局部坐标 |
| 网络包结构或顺序 | 升级 `ModNetwork.PROTOCOL_VERSION` |
| 燃料控制器 BlockEntity | 旧存档中拆除并重放旧方块 |

不要在已有存档上随意删除或重排注册对象。即使 Java 字段顺序看似无关，旧区块和物品仍可能
依赖已经写入存档的注册名或 ID。

## 12. 已知限制

1. 翠绿天体没有独立维度，表面传送暂时落到主世界重生点或世界出生点。
2. 四种新矿物没有自然生成，只能通过创造模式、命令或后续内容获得。
3. 气态巨行星和岩石卫星是可见但不可达的星图占位。
4. 飞船只有固定航线自动飞行；自由驾驶接口存在，但没有玩家控制、碰撞或推进玩法。
5. 专用服务器尚未形成稳定的发布验收矩阵，涉及 common/client 边界的改动仍需 `runServer` 实测。
6. 部分 `tools/*.ps1` 保留旧机器的绝对输出路径，运行前必须先检查并改为当前工作区。

## 14. 素材与工具

`tools/` 中的脚本分为三类：

- 方块和物品像素贴图生成：`gen_block_beautify.ps1`、`gen_resource_chain_textures.ps1` 等。
- 行星贴图回退生成：`gen_planet_beautify.ps1`、`gen_planet_sphere_textures.ps1`。
- 星图像素天体：`gen_starmap_pixel_body.ps1`，从 4K 表面图生成 64×64 或 128×128 球面资产。

生产用行星表面图是 4096×2048；星图天体使用独立的 64×64 总览贴图与 128×128 聚焦贴图。
运行生成脚本前先检查输入、输出、覆盖范围和绝对路径，不要直接覆盖已验收资产。
