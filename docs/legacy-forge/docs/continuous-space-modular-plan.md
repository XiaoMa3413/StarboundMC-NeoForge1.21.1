# 连续宇宙与多星系渲染 — 模块化实施计划

> **状态**：模块 0–5B 已完成；等待批准后实施模块 5C（星系环境连续混合）
> **创建日期**：2026-08-21
> **设计取向**：视觉效果与游戏体验优先，不追求现实绝对比例
> **实施原则**：一次只实施一个模块；每个模块独立构建、验证、提交、可回滚
> **关联模块**：`world/starmap/*`、`warp/ShipSpace`、`client/space/*`、`client/PlanetRenderer`、`client/StellarRenderer`、`client/ClientPlanetState`、`network/*`

---

## 0. 已批准的方案结论

本项目采用一个逻辑上连续、但为游戏节奏大幅压缩的宇宙空间。

- 星系之间允许连续飞行，不设置必须加载切换的硬边界。
- 跃迁仍然存在，但定位为高速旅行方式，而不是进入另一个星系的唯一方式。
- 恒星、行星、卫星之间的距离使用“玩法空间单位”，不解释为公里、AU 或光年。
- 保留当前较大的恒星核心、日冕、辐射效果、停泊视角和卫星距离。
- 恒星尺寸随距离变化，但使用可调的艺术化响应曲线，而不是严格的反距离物理公式。
- 未来增加大量星系时，使用扇区坐标、空间索引、浮动原点和恒星 LOD 控制性能。
- 附近少量恒星使用完整特效；远方恒星合并成批量星点，不逐颗绘制完整日冕。
- 当前自动航线继续工作，并作为未来自由驾驶控制器的第一个位姿提供者。

## 1. 当前基线

开始本计划前，工作区已经包含以下恒星与空间渲染改动：

- `StellarVisualProfile`：两个星系共享的恒星视觉定义。
- `StellarRenderer`：黄色恒星、红矮星、日冕、光芒、脉动、辐射弧和粒子的静态 VBO 渲染。
- `FrozenSkyRenderer`：冰冻星球天空使用相同的红矮星视觉配置。
- `ShipPoseProvider`：飞船虚拟位置与姿态的数据来源接口。
- `SpaceRenderContext`：空间渲染使用的逐帧只读快照。
- `StarSystemResolver`：根据当前虚拟坐标判断星系影响范围。
- `PlanetRenderer`：恒星天空壳层投影、行星远距离角尺寸投影和天体远近排序。
- `WarpFlashOverlay`：抵达闪光读取目标恒星颜色。

这些功能构成本计划的视觉基线。后续模块不得在没有独立视觉确认的情况下同时重写它们。

### 1.1 基线保护要求

- 黄色恒星和红矮星在各自星系中必须保持可见。
- 行星仍可遮挡恒星。
- 冰冻星球地表仍显示红矮星。
- 当前四颗可到达行星的停泊画面不得意外改变。
- 当前自动跃迁路线、燃料、存档和星图逻辑不得在模块 1–4 中改变。
- `.gradle-home/` 不纳入任何提交。

### 1.2 与旧计划的关系

[`ship-motion-warp-plan.md`](ship-motion-warp-plan.md) 仍负责当前自动航线、停泊视角和跃迁阶段机。

本文档只取代其中“虚拟坐标长期不会超过约 130k，因此无需大尺度坐标”的假设。当前自动航线行为仍以旧计划为准，直到本文档的模块 5 被单独实施。

## 4. 模块 1 — 连续坐标基础

模块 1 只建立新的坐标表达方式，所有现有对象仍位于扇区 `(0, 0, 0)`，因此理论画面和航线必须完全不变。

### 4.1 新增类型

建议新增：

```text
com.starboundmc.space
├── SectorCoordinate.java
├── UniversePosition.java
└── UniverseDelta.java
```

`SectorCoordinate` 保存三个 `long` 扇区坐标，负责相等、哈希和邻接偏移，不直接提交给 GPU。

`UniversePosition` 保存：

```text
SectorCoordinate sector
double localX
double localY
double localZ
```

- 推荐扇区边长：`100_000` 当前虚拟单位。
- 推荐局部坐标范围：`[-50_000, 50_000)`。
- 局部坐标越界时自动进位或借位到相邻扇区。
- 支持从旧 `Vec3` 创建，旧坐标默认进入扇区 `(0,0,0)`。

`UniverseDelta` 保存三个 `double` 相对分量。渲染、距离判断和局部飞行只使用相对向量；只有确认距离足够近时才转换为 Minecraft `Vec3`。

### 4.2 必须支持的运算

- `UniversePosition.fromLegacy(Vec3)`
- `UniversePosition.normalized(...)`
- `UniversePosition.add(UniverseDelta)`
- `UniversePosition.subtract(UniverseDelta)`
- `UniversePosition.deltaTo(UniversePosition)`
- `UniversePosition.distanceToSqr(UniversePosition)`
- `UniversePosition.sameSector(UniversePosition)`
- `SectorCoordinate.offset(dx, dy, dz)`

距离计算必须先处理扇区差，再组合局部坐标，不能先把巨大绝对位置压成单个 `float`。

### 4.3 接入范围

- `ShipPoseProvider`
  - 增加 `universePosition()`。
  - 提供从现有 `position()` 自动转换的默认实现。
- `SpaceRenderContext`
  - 增加本帧飞船 `UniversePosition`。
  - 暂时保留旧 `Vec3 shipPosition`。
- `StarSystem`
  - 增加连续宇宙导航位置访问器。
  - 当前 `navigationCenter` 自动适配为零号扇区位置。
- `StellarVisualProfile`
  - 增加恒星宇宙位置访问器。
  - 当前 `virtualPosition` 继续保留供旧代码使用。

### 4.4 明确不包含

- 不替换 `ShipFlightController` 的 `Vec3` 路线。
- 不修改 `SyncFlightPacket` 或 `ShipStateData`。
- 不改变当前星系判定和恒星尺寸公式。
- 不移动任何恒星或行星。
- 不增加自由驾驶、空间索引或 LOD。

### 4.5 数值测试

至少验证：

1. `(0,0,0; 10,20,30)` 与旧 `Vec3(10,20,30)` 完全一致。
2. `localX=50_001` 正确标准化到相邻扇区。
3. `localX=-50_001` 正确标准化到负方向相邻扇区。
4. 跨扇区边界前后，相对距离连续。
5. 相距百万个扇区的位置不会先转换为 `float`。
6. 当前全部天体转换后相对距离与旧代码一致。

### 4.6 验收标准

- 当前画面、航线时长、路径和停泊坐标无变化。
- `compileJava` 和完整 `build` 成功。
- 模块 1 独立提交，不包含模块 2 内容。

## 5. 模块 2 — 星系空间索引

### 5.1 目标

让运行成本取决于飞船附近的星系数量，而不是银河中注册的星系总数。

### 5.2 新增组件

新增 `GalaxySpatialIndex`：

- 星系注册后按 `SectorCoordinate` 建立静态空间哈希。
- 一个扇区可以包含多个星系。
- 查询指定扇区及周围 N 层扇区。
- 查询结果写入调用方提供的复用数组。
- 静态星系表改变时允许显式重建索引。

### 5.3 查询与缓存

- 飞船跨扇区时立即刷新。
- 同一扇区内移动超过阈值时刷新。
- 静止时最多每 10 tick 刷新一次候选集合。
- 每帧只更新候选星系的精确相对距离和屏幕参数。
- 初期查询周围 1–2 层扇区，最终由视觉距离配置决定。

`StarSystemResolver` 从遍历 `StarSystems.all()` 改为：

```text
空间索引查询候选
→ 计算候选影响权重
→ 写入复用 VisibleStar 槽位
→ 对少量可见恒星排序
```

### 5.4 性能预算

- 每帧精确计算的星系不超过 64 个。
- 完整影响判定的附近星系不超过 16 个。
- 不允许逐帧扫描未来的全部星系注册表。
- 不允许查询阶段创建与银河总星系数成比例的临时对象。

### 5.5 验收标准

- 当前两个星系的解析和画面与模块 1 一致。
- 大量测试星系下候选数量受查询半径限制。
- 跨扇区后索引正确刷新。
- 不出现缓存导致的恒星延迟跳入。
- 模块 2 独立提交。

## 6. 模块 3 — 艺术化恒星距离响应

### 6.1 目标

让玩家明确观察到恒星随飞船移动产生尺寸变化，同时保留当前较大的核心和日冕。

### 6.2 配置

将容易被误解为物理量的 `physicalVisualRadius` 迁移为：

```text
referenceDistance
baseSkyRadius
minimumLocalScale
maximumLocalScale
distanceResponseExponent
remotePointRadius
coronaActivation
effectActivation
```

推荐初始值：

| 参数 | 黄色恒星 | 红矮星 |
| --- | ---: | ---: |
| `baseSkyRadius` | 11.5 | 7.5 |
| `minimumLocalScale` | 0.65 | 0.60 |
| `maximumLocalScale` | 2.20 | 2.40 |
| `distanceResponseExponent` | 1.80 | 1.60 |
| `remotePointRadius` | 1.45 | 1.45 |

基准距离从当前各自主停泊位置计算，确保启用时停泊画面接近当前版本。

### 6.3 视觉公式

```text
distanceScale = clamp(
    pow(referenceDistance / currentDistance, distanceResponseExponent),
    minimumLocalScale,
    maximumLocalScale
)

localRadius = baseSkyRadius * distanceScale
finalRadius = lerp(remotePointRadius, localRadius, systemInfluence)
```

`systemInfluence` 必须连续变化，不能因为 `activeSystem` 字符串切换而瞬间改变尺寸。

### 6.4 特效权重

- 远景：核心亮点和极弱辉光。
- 接近：逐渐启用表面颜色、日冕和光芒。
- 本星系：完整特效。
- 近场：核心达到上限后，改为增强日冕、曝光和天空染色。
- 红矮星辐射弧在影响权重足够高后启用。

### 6.5 调试数据

开发环境应能查看星系 ID、恒星距离、影响权重、距离缩放、最终天空半径和当前 LOD。调试信息默认关闭。

### 6.6 验收路线

- 繁茂 → 荒芜：黄色恒星变化可见但不突兀。
- 繁茂 → 熔岩：短程变化较小。
- 第一星系 → 第二星系：红矮星从亮点连续成长为完整恒星。
- 第二星系 → 第一星系：黄色恒星连续成长，红矮星连续退化。
- 星系边界来回移动：无尺寸跳变或特效闪烁。

模块 3 完成实机截图确认后再提交。

### 6.7 第二星系布局校准

为避免使用视觉曲线掩盖过近的星系布局，第二星系作为一个整体平移，导航中心与第一星系保持约 `15,000` 单位距离。红矮星、冰冻星球停泊点和导航中心保持原有相对关系。两侧视觉影响外围之间保留深空间隔，不修改飞行控制器、存档或网络结构。跨星系航程因距离增加而达到现有 `28` 秒上限，需在视觉验收时同步确认游戏节奏。

## 7. 模块 4 — 远景恒星 LOD 与批量渲染

### 7.1 LOD 分级

#### LOD 0：完整恒星

- 完整核心、多层日冕、光芒、脉动。
- 红矮星辐射弧和粒子。
- 同时不超过 1–3 颗。

#### LOD 1：简化恒星

- 单层核心和单层辉光。
- 不绘制粒子和辐射弧。
- 同时不超过 8–16 颗。

#### LOD 2：远景星点

- 合并为一个批量 VBO 或单次 BufferBuilder 提交。
- 每颗只保存方向、大小、颜色和透明度。
- 同时最多 32–64 颗独立星点。
- 更远内容由普通星空背景承担。

### 7.2 判定依据

- 最终屏幕角尺寸。
- 星系影响权重。
- 连续空间距离。
- 是否为导航目标。
- 是否处于跃迁抵达阶段。

远景导航目标保留高辨识度的批量星点，避免被低透明度简化圆盘替换；进入简化范围后可以获得一级 LOD 提升，但不能绕过完整恒星数量上限。

### 7.3 绘制预算

- 完整恒星约 6–10 次 draw call/颗，最多 3 颗。
- 简化恒星最多 2 次/颗。
- 所有远景星点合并为 1 次提交。
- 普通星空不随星系数量线性增加。

### 7.4 验收标准

- 当前两个星系近景观感与模块 3 基本一致。
- 远景恒星不会变成方形或朝向错误。
- 增加测试星系后 draw call 不随总数线性增长。
- 4K 下无明显新增帧时间尖峰。
- 模块 4 独立提交。

### 7.5 分步实施边界

- 4A：只接入三档 LOD 判定、导航目标一级提升、完整恒星与简化恒星数量上限；星点仍逐颗使用轻量绘制。构建与视觉确认已完成。
- 4B：LOD 2 星点已合并为一次批量提交。远景系统恒星使用四层彩色光晕、白热核心和短四向星芒，与普通天空星区分；白热核心直径约为天空盒最大星点的 `1.6` 倍，外晕直径约为其 `3–4` 倍。普通天空星尺寸统一缩小 `15%`，不改变数量和亮度。相邻 LOD 之间使用每级约 `18 tick` 的交叉淡化，并共享一条连续恒星亮度曲线。远景辨识度与切换连续性已完成实机确认，模块 4 已完成。

## 8. 模块 5 — 连续跨星系航行与浮动原点

模块 5 最后实施，并拆成多个子提交。它是唯一允许改变服务器航行、网络和存档的模块。

### 8.1 服务器权威状态

飞船存档增加：

```text
ShipSectorX / ShipSectorY / ShipSectorZ
ShipLocalX / ShipLocalY / ShipLocalZ
ShipVelocityX / ShipVelocityY / ShipVelocityZ
```

旧存档继续读取原 `ShipX/Y/Z` 并转换到零号扇区。

### 8.2 网络同步

- 扇区坐标在改变时或完整快照中发送。
- 局部坐标、速度和姿态按现有节奏同步。
- 插值只在局部相对坐标中执行。
- 客户端和服务器模组版本仍要求一致。

### 8.3 浮动原点

- 飞船跨越局部阈值时改变扇区并重新居中局部坐标。
- 渲染始终使用 `天体 UniversePosition - 飞船 UniversePosition`。
- GPU 只接收相机附近的 `float` 相对坐标或天空壳层坐标。
- 船体方块仍固定在飞船维度世界锚点，不移动区块。

### 8.4 星系环境连续混合

星系影响权重连续控制星空颜色、环境音乐、辐射环境、导航 UI 和可见天体。当前星系 ID 只用于 UI、存档和规则，不允许直接造成画面硬切。

### 8.5 跃迁与普通飞行

- 普通飞行沿连续宇宙坐标积累位移。
- 跃迁在同一坐标上高速推进，使用视觉隧道隐藏极大速度。
- 到达时在目标连续坐标附近减速，不切换到另一套局部场景。
- 现有预设航线继续作为自动驾驶模式。

### 8.6 子模块

1. 5A：存档与网络支持扇区坐标，但行为不变。
2. 5B：自动航线支持跨扇区。
3. 5C：星系环境连续混合。
4. 5D：未来自由飞船控制器接入 `ShipPoseProvider`。

### 8.7 模块 5A 实施记录

本子模块严格限于兼容层，没有启用跨扇区航行：

- `ShipStateData` 以 `UniversePosition` 和 `UniverseDelta` 保存飞船位置、速度。
- 新存档写入扇区、局部坐标和速度字段；同时保留旧 `ShipX/Y/Z` 兼容字段。
- 旧存档缺少新字段时继续读取 `ShipX/Y/Z`；非法或溢出位置安全回退到当前行星停泊点。
- `SyncFlightPacket` 同步 `long sector + double local + double velocity`，网络协议版本提升到 `4`。
- 客户端保留原 `Vec3` 自动航线采样，通过同步位置加局部插值增量提供 `UniversePosition`。
- 客户端登录/退出时重置快照版本代次；服务器重启后从 `revision=0` 恢复同步时，不再把途中快照误判为旧包。
- `ShipFlightController`、航线时长、燃料消耗和天体布局均未修改。

自动验证覆盖旧存档迁移、新格式精确往返、局部坐标标准化、旧字段保留、数据包往返、零号扇区客户端位置兼容，以及服务器重启后的快照版本重置。共 `26` 项测试通过，完整 `build` 成功。旧存档加载、现有航线和跃迁中退出恢复均已完成实机验证；重进存档后飞船会继续动画与运动，不再静止等待后瞬移。

### 8.8 模块 5B 实施记录

本子模块让自动航线原生使用连续宇宙坐标，但不移动当前星系，也不增加新航线：

- `ShipFlightController` 的规范位置和速度改为 `UniversePosition` / `UniverseDelta`。
- `UniverseRouteFrame` 以出发点为局部原点计算避障曲线，跨扇区时只规范化整数扇区，不改变相对轨迹。
- 起点和终点使用精确宇宙锚点，中间曲线使用相对双精度坐标，避免抵达坐标残留浮点尾差。
- `ShipSpace` 为停泊点和行星中心提供宇宙坐标；旧 `Vec3` 访问器继续保留。
- 服务器存档和网络快照直接读取控制器的宇宙位置/速度，不再先降级到局部 `Vec3`。
- 客户端在宇宙坐标上重采样确定性自动航线；旧位置接口只返回当前扇区局部坐标。
- 行星距离和视图变换改为 `天体 UniversePosition - 飞船 UniversePosition`，跨扇区边界不会产生屏幕跳动。
- 空间索引仍只查询附近扇区，但固定为当前星系和导航目标预留最多两个候选槽位，远距离目标不会因性能裁剪消失。
- 航线阶段、最长 `28` 秒时长、燃料规则、避障形状和当前天体布局均未修改。

自动验证覆盖正负扇区边界连续性、当前全部 `12` 条有向航线、恢复进度、宇宙速度、索引预算和远距离导航目标保留。共 `32` 项测试通过。当前短程、同星系长程、跨星系航线及跃迁恢复已完成实机验证，视觉轨迹与模块 5A 基本一致。

### 8.9 模块 5C 实施记录

本子模块只统一星系环境的连续权重，不改变航线、坐标、恒星尺寸或游戏规则：

- `GalaxyEnvironmentBlend` 从附近恒星解析结果生成可复用的环境快照，不增加逐帧集合分配。
- 每个星系的影响权重同时提供给天空染色、导航界面和未来环境音轨混音；当前没有环境音乐素材，因此未接入跃迁音效或新增音频资源。
- 天空背景沿用模块 3、4 已确认的颜色和强度公式，但改为读取共享快照，停泊画面理论上保持不变。
- 深空权重、环境总占比、主导星系、混合天空色和辐射强度均由连续位置计算；辐射目前只作为环境信息显示，不造成伤害。
- 星图的跨星系自动视图根据出发地和目的地的实际环境影响切换，不再直接依赖离散飞行阶段。
- 星图自动视图使用共享权重，但不在界面上显示环境或辐射数值；星图视觉与交互改进留待下一独立步骤。
- 本模块不实现自由驾驶控制器，不进入 5D。

自动验证覆盖两个星系停泊环境、影响边缘的连续衰减和两星系之间的中性深空；当前共 `35` 项测试通过，完整 `build` 成功。仍需实机确认：黄矮星停泊天空不变、红矮星环境正确、深空过渡中性、星图视图按位置依次推进。

### 8.10 模块 5D 实施记录

本子模块只完成未来自由控制器与现有空间渲染的接口边界，不实现实际操控：

- 新增 `FreeFlightPoseProvider`，自由控制器只需提供 `UniversePosition`、`UniverseDelta` 速度以及 yaw、pitch、roll。
- 本地 `Vec3` 位置和速度由连续宇宙数据生成；跨扇区时局部位置自动重新居中，控制器不需要管理浮点原点。
- 自动航线阶段、目标天体和星系提示默认处于非跃迁空值状态；星系选择继续根据飞船真实宇宙坐标解析。
- `SpaceRenderState` 继续作为唯一渲染位姿切换点，现有自动航线适配器保持不变。
- 接口仅提供客户端视觉快照，不把飞船位置控制权交给客户端，也不新增输入、推力、碰撞、燃料或网络协议。

自动验证覆盖自由位姿快照、默认非跃迁状态，以及正方向跨扇区时局部坐标重置而恒星相对坐标连续；当前共 `37` 项测试通过，完整 `build` 成功。该子模块理论上不改变现有自动航线和画面。

## 11. 性能与精度预算

### CPU

- 不按银河总星系数逐帧遍历。
- 天体排序只处理可见集合。
- 使用复用数组或固定容量缓冲。
- 不在每帧构造星系级网格。

### GPU

- 完整特效恒星最多 3 颗。
- 远景恒星统一批量提交。
- 行星纹理球继续复用静态 VBO。
- 小于屏幕阈值的行星不绘制大气。

### 精度

- 宇宙坐标使用 `long sector + double local`。
- 相对坐标保持双精度直到最终提交。
- GPU 不接收巨大绝对坐标。
- 天空天体继续投影到安全壳层。

## 14. 风险与缓解

| 风险 | 缓解方式 |
| --- | --- |
| 坐标类型扩散过快 | 模块 1 只增加兼容接口，不替换全部 `Vec3` |
| 星系切换造成尺寸跳变 | 模块 3 使用连续影响权重，active ID 不硬切尺寸 |
| 大量恒星造成 draw call 爆炸 | 模块 4 限制完整恒星数量并批量绘制远景 |
| 扇区边界位置跳动 | 只渲染两点相减后的相对坐标 |
| 旧存档无法加载 | 新字段提供默认值，旧位置字段保留到 M5 完成 |
| 连续飞行耗时过长 | 距离继续服务游戏节奏，并保留高速跃迁 |
