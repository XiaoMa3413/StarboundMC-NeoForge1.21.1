# 星图像素复古终端美术与扩展计划

> 状态：ART-0～ART-5 已完成，计划关闭
> 编写日期：2026-08-23
> 目标分支：`codex/starmap-retro-terminal-art`
> 技术基线：高密度 UI 计划已完成（`63833a4`）

## 1. 最终方向

星图采用“像素复古未来主义飞船终端”风格。

它应当看起来像飞船中真实存在的一台导航设备，而不是普通软件窗口：外层是有结构的
工业机框，内部是深色终端显示区，天体、轨道和数据卡由高对比度仪器图形呈现。

《Starbound》提供以下参考：

- 强烈的设备感和像素构造。
- 黑色导航显示区与清晰的仪器线条。
- 分段信息卡和一眼可辨的状态层级。
- 美术风格服务于世界观，而不只是把数据排在矩形面板里。

本项目不复制：

- 绿色单色主题。
- 原版具体边框、图标、工具栏或详情卡形状。
- 浮动详情卡遮挡星图的布局。
- 原版界面素材和逐像素构图。

## 2. 本项目的独立视觉身份

### 2.1 颜色

推荐第一版：

- 石墨深蓝：设备外壳和结构暗部。
- 近黑蓝：导航显示屏。
- 冷青色：主要终端线条、选择和有效操作。
- 琥珀色：燃料、威胁和需要关注的信息。
- 暗红色：锁定、错误和不可用状态。
- 灰白色：主要文字，蓝灰色：次要文字。

冷青色取代《Starbound》的绿色荧光，形成项目自己的识别色。恒星和行星本身的颜色不受
界面主题限制。

### 2.2 形状

- 外框采用阶梯式切角、分段厚边和局部内凹结构。
- 显示屏使用清晰的像素边缘与暗色内框，不做现代圆角玻璃卡片。
- 标题、指标和状态使用窄条标签帽或插槽式分段。
- 机械细节使用少量接缝、固定点、短刻度和导轨，不铺满装饰。
- 框体允许看起来厚重，但不得占用新的布局空间；装饰必须落在现有边距内。

### 2.3 像素规则

- 设备外壳和控件采用清晰的像素阶梯，不使用抗锯齿圆角。
- 2× 高密度层允许半逻辑像素细节，但图案仍按稳定的虚拟像素网格设计。
- 天体贴图保持现有像素艺术。
- 轨道线、飞船和必要的数据连线可以保持细线，以免所有元素都变得粗重。
- 不使用全屏扫描线；如果后续需要屏幕质感，只允许极淡、静态、可关闭的局部纹理。

## 3. 功能与布局边界

### 必须保留

- 近全屏响应式布局。
- 宽屏固定右侧详情终端。
- 低逻辑分辨率详情抽屉。
- 星域、恒星系、行星聚焦三级导航。
- 当前天体尺寸、位置、贴图、卫星轨道和选择逻辑。
- 跃迁自动切页、飞船动画、燃料与进度同步。
- Minecraft 原生中英文字体。

### 不在本计划中实现

- 不新增星系、天体属性或玩法数值。
- 不新增辐射、环境或资源数据来填充界面。
- 不重做已经验收的行星贴图。
- 不改变跃迁路线、燃料规则、网络或存档。
- 不显示没有真实内容的类别按钮。
- 不引入自定义中文字库或全屏 RenderTarget。

## 4. 信息与装饰层级

视觉优先级从高到低：

1. 天体、当前选择和跃迁状态。
2. 页面/天体名称与主要操作。
3. 威胁、燃料、可达性等关键数据。
4. 描述文字和辅助状态。
5. 外壳接缝、刻度、固定点等装饰。

执行约束：

- 地图画布始终比机框装饰更抢眼。
- 同一区域只保留一个主要冷青高亮，不让所有边线同时发光。
- 琥珀色和红色必须保持稀缺，避免失去状态意义。
- 装饰不得进入文字安全区、点击区或 Scissor 边界之外。

## 5. 主题与扩展结构

### 5.1 主题令牌

新增 `StarmapVisualTheme`，集中管理：

- 外壳、凸起板、内凹槽和显示屏的分层色。
- 普通边、亮边、阴影边与荧光线色。
- 主要、注意、危险、当前和已探访状态色。
- 主文字、次文字和禁用文字色。
- 切角尺寸、厚边尺寸、刻度长度和 section 间距。

Chrome、Overlay、Detail 和星图专用按钮不得各自保留重复语义色。恒星和行星的自然
颜色、贴图采样色不并入 UI 主题。

### 5.2 通用像素终端图元

在高密度绘制层上提供：

- 阶梯切角框。
- 三层像素机框（亮边、面板、暗边）。
- 内凹显示槽。
- 分段标签帽和窄状态轨。
- 短刻度、固定点和断续导轨。
- 主要操作按钮的机械按键底座。

图元使用直接几何绘制，不为每个面板生成独立纹理。

### 5.3 可扩展详情内容

新增轻量不可变模型：

- `StarmapDetailContent`：标题、副标题、描述和 section 列表。
- `StarmapDetailSection`：稳定 id、可选标签帽和内容行。
- `StarmapDetailLine`：文本、语义状态和未来可选图标 id。
- `StarmapDetailContentFactory`：从星系、恒星或天体生成内容。

`StarmapDetailRenderer` 只负责绘制终端卡片，业务状态仍由现有客户端数据提供。

详情呈现原则：

- 扫描、导航、状态等真实信息在同一详情页直接展示，不增加类别切换按钮。
- section 继续使用稳定 id，为未来信息模块保留数据扩展能力，但不据此隐藏内容。
- 不把当前少量内容人为拆成多个页面，也不要求玩家记忆信息所在标签。
- 宽屏详情和紧凑抽屉复用同一内容模型与直出顺序。

## 6. 分阶段实施

### ART-0：像素终端设计基础

状态：已完成并通过实机视觉确认（2026-08-23）。

实施：

- 新增 `StarmapVisualTheme`。
- 将 Chrome、Overlay、Detail 和按钮的语义色迁移到主题。
- 新增切角框、三层机框、显示槽、标签帽、刻度和固定点图元。
- 初始色值保持当前视觉，先完成结构抽取。

不做：

- 不改变现有界面造型、内容和交互。

验收：

- 抽取前后截图基本一致。
- 所有 UI 语义色和机械尺寸有单一来源。
- 图元不创建动态纹理或每帧集合。

### ART-1：飞船终端外壳

状态：已完成并通过实机视觉确认（2026-08-23）。

实施：

- 将主面板改造成阶梯切角的像素工业机框。
- 重做标题板、显示屏内框、详情终端外壳和底部结构。
- 在现有边距内加入少量接缝、固定点、短刻度与分段导轨。
- 燃料条改为嵌入式仪表槽，但保留尺寸、数值和位置。

不做：

- 不修改星图画布内容和详情内部排版。
- 不改变任何点击框。

验收：

- 第一眼像一台飞船导航设备，而不是普通蓝色窗口。
- 机框具有明显像素构造，但没有明显压缩地图面积。
- 宽屏和紧凑布局无断边、重叠或抽屉泄漏。

### ART-2：复古终端详情卡

状态：已完成并通过实机视觉确认（2026-08-23）。

实施：

- 引入 `StarmapDetailContent`、section 和 line 模型。
- 将名称、类型、威胁、描述、燃料和状态改造成分段终端信息卡。
- 使用标签帽、内凹文本区、窄状态轨和像素分隔条建立层级。
- 为未来详情 section 和小图标保留扩展结构，但不显示空位。
- 宽屏和抽屉使用同一排版模型。

不做：

- 不新增环境、辐射或资源数值。
- 不改变跃迁按钮逻辑。

验收：

- 中文长文本正确换行、截断，不与机框装饰冲突。
- 当前、已探访、锁定、威胁和燃料信息清晰可辨。
- 紧凑抽屉中的关闭、内容裁剪和主要操作层级正确。

### ART-3：导航显示屏协调

状态：已完成并通过实机视觉确认（2026-08-23）。

实施：

- 将画布外缘处理为内嵌终端显示屏。
- 微调星空层次、轨道线亮度和选择/悬停环，使其适配复古终端外壳。
- 可加入非常克制的边缘坐标刻度或角部校准标，不覆盖天体区域。
- 检查星域恒星、恒星系天体和聚焦天体的视觉权重。
- 如调整 `StarMapCanvas`，为缓存键加入明确视觉版本。

不做：

- 不改变天体位置、尺寸、贴图或卫星交互。
- 不恢复青色停靠环和已探访状态点。
- 不修改飞船运动曲线和跃迁阶段。

验收：

- 显示屏具有终端设备感，天体仍是最清晰的主体。
- 轨道线可见但不压过天体和标签。
- 星空不会与远景恒星、文字或选择框争夺注意力。

### ART-4：机械控件与交互反馈

状态：已完成并通过实机视觉确认（2026-08-23）。

实施：

- 将返回、进入、跃迁和关闭按钮统一为像素机械按键。
- 区分普通、悬停、键盘焦点、禁用和主要操作状态。
- 使用局部亮边、按下内缩或短状态条表达反馈，不新增循环闪烁。
- 保持详情信息单页直出，不新增类别切换入口。

验收：

- 点击框、鼠标、键盘、旁白和禁用提示不回退。
- 按钮具有实体设备感，但文字仍清晰居中。
- 未来新增 section 不要求修改 Screen 的绘制流程。

### ART-5：统一校准与计划关闭

状态：已完成（2026-08-23）。本阶段不改变已验收视觉。

实施：

- 统一机框、详情、显示屏和控件的像素尺度与色彩权重。
- 删除临时样片、重复常量和未使用的装饰分支。
- 检查所有分辨率、页面和跃迁状态。
- 更新计划的提交与最终决策记录。

ART-5 不顺带实现新的玩法或详情类别。验收后，再单独决定下一项功能。

收尾结果：

- 核对 Chrome、Detail、Overlay 和机械按钮的主题令牌与虚拟像素尺度。
- 确认仓库中没有遗留 HD 对比样片，终端图元均有实际调用。
- 合并按钮边缘与外壳高光、内框、选择色的重复别名，保持实际色值不变。
- 保留单页直出详情，不重新引入类别切换或空扩展入口。
- 完成响应式布局、密度换算、详情模型、导航状态和跃迁相关自动测试。

## 7. 实施与提交规则

- ART-0～ART-5 每阶段独立提交并推送。
- 产生视觉变化的 ART-1～ART-4 必须先实机确认，再提交。
- 出现审美问题时暂停当前阶段微调，不将问题带入下一阶段。
- 每阶段运行 `git diff --check` 与 `gradlew test`。
- `.gradle-home/` 始终不提交。

实机覆盖：

- 星域、恒星系和行星聚焦三页。
- 宽屏详情终端和低逻辑分辨率抽屉。
- 普通、选择、悬停、锁定、当前、已探访和燃料不足状态。
- 同星系跃迁、跨星系自动切页与中途重开星图。
- GUI Scale 1、2 及更高档位。

## 8. 性能边界

- 主题和详情模型使用轻量不可变对象。
- 静态机框由高密度图元绘制，不新增全屏纹理。
- `StarMapCanvas` 继续使用现有高分辨率纹理和 LRU 缓存。
- 美术调整不得增加每帧纹理上传。
- 不增加持续闪烁、全屏混合或高频随机噪点。

## 9. 决策记录

2026-08-23：

- 最初的“深空航电＋轻度像素工业”方案未锁定。
- 最终采用“像素复古未来主义飞船终端”。
- 《Starbound》作为设备感、像素构造和信息层级参考，不作为复制目标。
- 使用石墨深蓝机框、近黑显示屏、冷青终端线和琥珀状态色，避免绿色复刻。
- 保留固定右侧详情终端与紧凑抽屉，不采用遮挡星图的浮动卡片。
- 为真实二级内容预留接口，但不显示空类别。
- ART-3 的选择环、悬停环和动态星核统一以静态画布的逻辑像素中心定位，避免
  2× 高密度绘制产生半逻辑像素偏移；四向选择刻度保持成对对称。
- ART-4 实机评估否决了详情类别切换按钮：当前信息量适合在单页同时展示，额外切换
  会增加点击和记忆成本；section 稳定 id 仅用于数据扩展，不直接映射为二级菜单。
- ART-5 仅执行无视觉差异的令牌合并、注释校准和回归检查，美术计划至此关闭。
