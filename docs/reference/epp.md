# EPP、生命支持与 EVA

本文描述当前装备规则；具体范围、配方、容量与速率由当前代码/config/数据资源定义。未完成的人工验收和未来方向见[当前工作](../current-work.md)。

## 装备与个人状态

- EPP 使用原生独立装备槽和统一 equipped resolver。穿戴的物品承载其物品状态；个人氧气/暴露等附件是服务端权威，客户端 HUD 只显示快照。
- Mk I 至 Mk III 与当前供氧、温控模块、EPP 工作站已实现。安全区域为明确的环境规则，不是整艘船的压力/密闭模拟；可呼吸环境与温度风险分别判断。
- 当前温控是匹配模块保护：正确模块提供保护，重复模块不叠加；无保护的暴露与恢复遵循现有固定规则，不根据历史计划补连续温度系统。
- 模块弹窗使用实际菜单槽位，服务器校验 container、同步版本、槽位权限、索引和模块兼容性。工作站模块操作仍是当前功能，不能因新弹窗存在而删除。
- 装备页和已确认的黑灰视觉保持；死亡、keepInventory、重连等语义由当前附件/库存生命周期和测试约束。

## EVA 与 Relay

- Mk III 提供当前 EVA 能力；离船距离、安全、返船与紧急召回由服务端验证，客户端标记不授予行动权限。
- 当前 Relay 是一个 authored station，具有动态锚点、snapshot、船员安全与恢复边界。持久 journal、失败保留现场等 invariant 见[架构](../architecture.md)；不是任意多 POI 生成系统。
- 船员在舱外时的航行门禁与安全返回不得被 UI 便利操作绕过。

## 创造模式原型

JumpThruster 当前只通过创造模式获取，使用独立 Mobility 槽；不接入生存配方、任务或探索奖励。一次腾空的推进额度只在稳定落地后重置，空中换装不重置；原版跳跃/创造飞行保留，跌落保护只在实际装备时生效。第三人称穿戴模型与生存获取方式尚未完成。

辐射、Mk IV、连续压力模拟、多 Relay/空间 POI 都不是当前已实现合同。
