# 飞船维度太空视觉增强计划

> 状态：星系间距已视觉确认；亚光速节奏与超空间行星过渡修复已实现并通过自动测试，等待客户端视觉确认；S0 尚未开始
>
> 目标版本：Minecraft 1.21.1 / NeoForge 21.1.248
>
> 建立日期：2026-09-02
>
> 当前建议：先视觉确认跨星系航行的亚光速节奏，再归档尺度阶段并进入 S0 普通太空背景

## 目标与范围

本计划增强玩家在飞船维度中透过舷窗观察太空时的视觉效果。第一目标是让停靠和普通航行不再只是
“蓝黑渐变加均匀星点”，第二目标是让行星从静态贴图球升级为具有独立材质特征的天体，第三目标是
让近距离恒星拥有与升级后行星相称的球体体积感。

本轮不重做已经视觉确认的跃迁隧道，不修改星图 UI，不改变飞船真实方块位置，也不新增与渲染无关
的玩法规则。现有实现详见[飞船维度太空渲染基线归档](archive/ship-space-visual-baseline.md)。

## 前置阶段：星系尺度重新校准

当前尺度确实会削弱“跨恒星系”的距离感：两个导航中心只相距约 `14,988` 单位，影响范围之间约有
`4,988` 单位的纯深空。从初始翠绿星球附近观察，己方恒星约在 `24,478` 单位外，第二星系红矮星
约在 `26,016` 单位外；两者几乎处在同一距离层级。

推荐调整：

- 将第二恒星系作为一个完整星团平移，而不是只移动红矮星或冰冻星球。导航中心、恒星、冰冻星球、
  停靠点和相关坐标必须使用同一个平移量，保持第二星系内部已经建立的相对关系。
- 将两个导航中心的目标间距暂定为约 `35,000–45,000` 单位，最终值通过世界天空和星图画面共同
  验收。这样第二恒星系主星从初始区域观察时约为己方主星距离的两倍，能够明显退到远景层级。
- 两个影响半径暂时保留 `5,500` 和 `4,500`。扩大中心距离后，星系之间会形成更宽的真正深空区，
  也为 S1 的环境色渐隐提供充足过渡距离。
- 深空星图的美术坐标与宇宙坐标相互独立，因此也要单独拉开两个系统节点，并延长中间的超空间航道；
  不能只改真实坐标而让星图看起来仍然拥挤。
- 保留当前 100 点跨星系燃料成本。距离变化属于世界尺度和视觉叙事调整，不自动改变现有经济规则。
- 当前跨星系航行约 27.3 秒，已经接近 28 秒上限。建议继续保留这个上限，不用更长的等待时间证明
  星系很远；超空间航行本身就应跨越巨大的距离。

兼容性要求：

- 已停靠的旧世界在服务器初始化时会按当前行星重新锚定到停靠坐标，仍需加入回归测试确认第二星系
  旧存档不会短暂出现在旧位置。
- 正处于跨星系航行中的存档保存了飞船宇宙坐标。修改坐标前需要为“航行中升级版本”确定迁移策略，
  至少验证恢复后航线不会跳回、卡住或穿过天体。
- 坐标调整必须同步覆盖航线避障、恒星候选查询、星系影响混合、抵达位置和星图航线测试。

验收重点：在第一星系停靠时，第二星系只作为遥远目标或微弱恒星存在；两个星系之间出现明确深空
过渡；进入第二星系后，其内部行星尺寸、恒星方向和停靠画面与调整前保持一致。

## 美术方向

整体风格采用**克制、清晰、具有纵深的科幻深空**：

- 行星、近距离恒星和航行目标仍是第一视觉焦点，背景不能用高亮星云抢夺注意力。
- 大尺度色块使用低频、柔和的变化；避免密集噪点、整屏扫描线和快速全屏闪烁。
- 星点不再平均铺满画面，而是形成疏密差异、局部星团和一条非常宽且很淡的银河尘带。
- 不同星系有自己的环境气质，但颜色通过现有影响权重连续混合，不能在跨越边界时突然换色。
- 行星应通过光照、云层、大气和材质特性形成差异，而不是统一套用更强的外发光。
- 普通停靠画面保持安静；只有飞船确实进行亚光速移动时才出现轻微、低频的视差。
- 所有效果必须在宽屏、窄窗口和不同 GUI Scale 下保持舒适。太空渲染不依赖 GUI 像素坐标，画面
  边缘不得出现贴图接缝或固定方框。

## 分阶段方案

### S0：深空背景与星点分层

目的：以最低风险解决当前普通太空“空、平、均匀”的问题。

计划内容：

- 将单一蓝黑穹顶扩展为三个相互独立但统一旋转的视觉层：
  1. **底层深空色场**：保留接近黑色的主底色，加入范围很大的冷色低频明暗变化；
  2. **远景银河尘带**：使用一至两条宽阔、低对比、边缘松散的程序化带状结构；
  3. **背景星层**：保留现有星点总量与冷暖差异，但按方向场重新分配为稀疏区、普通区和小型星团。
- 星云与尘带优先使用固定种子的缓存几何或低分辨率原创纹理，只在资源初始化或配置改变时重建，
  不在每帧生成噪声。
- 背景仍服从飞船虚拟航向，不能粘在玩家屏幕上；玩家在船内走动时也不得出现天空漂移。
- 保留足够的纯暗区域，让行星轮廓、舷窗框架、HUD 和文字保持清晰。

人体工程学约束：

- 尘带峰值亮度显著低于普通星点，覆盖范围可以大，但不形成发白的整屏雾层。
- 背景层不进行高频闪烁；只有少量星点保留现有幅度很小的独立闪烁。
- 不使用细密规则网格、满屏微粒或高对比彩色噪声，避免长时间停留在飞船内产生视觉疲劳。

验收重点：停靠时画面明显更有纵深；任意转向看不到立方体接缝；背景不会盖过行星和恒星。

### S1：星系环境差异

目的：让玩家仅凭舷窗画面也能感受到身处不同恒星系，而不依赖 UI 标签。

计划内容：

- 复用 `GalaxyEnvironmentBlend` 的连续权重驱动尘带色相、背景冷暖、星点密度偏置和极少量环境辉光。
- 黄色恒星附近偏向低饱和暖白与冷蓝共存；高辐射或红色恒星附近可增加暗红、琥珀色尘埃倾向，
  但主底色始终保持深黑蓝。
- 深空区域逐步降低主导星系染色，使环境自然回到更中性的冷色，而不是按星系 ID 瞬间切换。
- 辐射强度只控制很缓慢、很轻的环境呼吸或日冕活跃程度，不直接制造全屏报警闪烁。

验收重点：两个已有恒星系可被感知为不同环境；在航行过渡中颜色连续；环境色不会改变星球贴图
本身的辨识度。

### S2：行星材质与动态层次

目的：保留现有行星贴图与球体辨识度，解决表面完全静止、光照偏平和四类行星材质表现过于一致的
问题。

现状判断：

- 四张行星表面贴图已经是 `4096 × 2048`，提高到更大分辨率只会增加显存和加载成本，不是正确
  优化方向。
- 当前球体网格已经足够圆润，但表面方向永远固定；每颗行星的光照颜色被烘焙进缓存 VBO，因此
  不能在保持恒星方向不变的同时正确旋转表面。
- 当前大气是一层按行星换色的均匀加法辉光，没有昼夜侧差异，也没有云层或材质专属效果。

第一轮低风险增强：

- 将通用光照曲线拆成行星材质配置：分别控制日照强度、夜侧环境色、明暗交界柔和度和色彩饱和度，
  避免所有行星都出现相同的暖色明暗交界。
- 把大气改为内外两层：贴近边缘的薄亮层负责轮廓，外侧宽而淡的层负责空气散射；亮度主要集中在
  受光侧和明暗交界附近，夜侧只保留很弱的轮廓。
- 按类型区别处理：翠绿星球突出蓝色大气与海洋高光，熔岩星球突出裂隙自发光，冰冻星球突出冷色
  边缘散射，荒芜星球保持干燥、低亮且几乎没有大气。
- 不直接修改原始 4K 颜色贴图。需要专属效果时新增较小的原创灰度材质遮罩，由渲染器控制强度，
  避免把辉光永久画死在表面贴图中。

第二轮动态增强：

- 为每颗行星加入很慢的自转，并保留已有轴倾角；不同星球可以有不同周期，但玩家观察十几秒后才
  应明显察觉移动，不能像星图节点那样快速公转。
- 推荐把共享球体升级为带 UV、法线和材质参数的轻量行星渲染路径，使纹理旋转时恒星光照仍固定在
  宇宙方向。不得直接旋转当前已经烘焙光照的 VBO，否则明暗面会跟着地表一起转动。
- 翠绿星球可增加一层略高于地表、以不同慢速旋转的稀薄云层；其他行星只有在美术上确有需要时才
  增加覆盖层，不能统一套云。
- 表面旋转、云层和大气变化均使用游戏时间与 partial tick，暂停或帧率波动后不应跳动。

人体工程学约束：

- 禁止快速自转、强烈周期性呼吸、整颗行星闪烁或大面积过曝。
- 夜侧仍需保留足够轮廓，但不能为了“看清”而失去昼夜对比。
- 材质特效在行星投影尺寸较小时自动淡出，避免远景出现彩色噪点和闪烁边缘。

验收重点：四类行星即使不看颜色也有不同材质气质；自转缓慢且光照方向稳定；大气边缘自然；原有
贴图细节和行星身份没有被遮罩或强光破坏。

### S3：近距离 3D 恒星核心

目的：让 `FULL` LOD 的近距离恒星像现有行星一样拥有真实球形轮廓和可感知的表面运动，同时保留
恒星应有的自发光特性。

推荐实现：

- 新建一份共享的低至中精度 UV 球体 VBO，仅替换 `FULL` LOD 的恒星核心；`POINT` 和
  `SIMPLIFIED` 路径保持现状，以保护远景密度和性能。
- 恒星球体借用行星的“球形几何 + 球面纹理”思路，但**不复制行星的昼夜明暗面**。恒星表面为
  自发光材质，使用低频颗粒、缓慢色带或少量暗斑体现表面结构。
- 使用一张项目原创的灰度球面纹理作为公共细节，再按 `StellarVisualProfile` 的表面色、核心色和
  日冕色进行染色；这样无需为每颗恒星维护独立高分辨率贴图。
- 表面以非常缓慢的速度旋转。旋转只帮助玩家识别球体，不应像行星公转或风扇一样明显。
- 现有日冕、辐射弧、星芒、粒子和脉动作为球体外层保留；降低圆盘核心的旧亮度，避免二维圆盘与
  新球体重叠后过曝。
- `FULL` LOD 仍最多同时出现 3 颗。球体 VBO 与纹理共享，运行中不产生逐帧对象或重复上传。

为什么不让所有恒星都变成球体：远距离恒星投影只占几个像素，球体网格既不可见又会增加绘制开销；
现有三级 LOD 正好允许在近处提升质量、在远处维持星海密度。

验收重点：近处恒星边缘稳定圆润，转动时能看出表面结构；它看起来是发光球体而非被恒星照亮的
行星；远处恒星的大小、亮度和切换过程不退步。

### S4：亚光速航行的轻微视差

目的：在不移动玩家和飞船方块的前提下，让普通航行比完全静止更有速度感。

计划内容：

- 底层深空色场近似无限远，只随航向旋转，不产生明显平移。
- 远景星层产生极弱位移，中景稀疏尘埃产生稍强位移，由飞船虚拟速度和方向共同驱动。
- 启动和停止采用平滑缓入缓出；停靠状态最终完全稳定，不保留持续漂移。
- 视差幅度设置为“需要观察几秒才察觉”，不把亚光速航行做成缩小版超空间隧道。
- 转向仍由整套天空共同响应，位移视差不能破坏星系坐标与目标天体的方向一致性。

验收重点：航行中有柔和的空间流动感；停靠后背景不漂移；快速转头不会产生晕动、拖影或星点跳变。

### S5：整合与可选细节

仅在 S0–S4 全部视觉确认后考虑：

- 微调新背景与现有跃迁隧道的淡入淡出，使进入超空间时背景逐步退居次要位置。
- 评估极轻微的舷窗冷光反射；只有能准确限制在玻璃材质上时才实现，不使用覆盖全屏的假反光。
- 增加客户端视觉质量选项，例如关闭星云、降低恒星表面细节或禁用亚光速视差。

这些内容不阻塞主体方案，也不应先于深空背景、行星和 3D 恒星实施。

## 推荐开发顺序

1. 完成星系尺度前置阶段，先用测试确认整体平移与旧存档行为，再核验世界天空和深空星图的距离感。
2. 完成 S0 的背景原型，只调整普通停靠画面，交由客户端视觉验收。
3. 在 S0 基础上接入 S1 连续环境参数，分别在两个恒星系和扩大的深空位置对比。
4. 先完成 S2 的光照与大气低风险增强，再决定并实现正确的行星自转渲染路径。
5. 单独制作 S3 `FULL` 恒星球体原型，先替换一颗近距离恒星的核心，确认美术方向后再通用化。
6. 完成 S3 的 LOD 过渡与性能验证。
7. 最后实现 S4 亚光速视差，避免背景结构和运动逻辑同时变化而难以定位视觉问题。
8. 仅在全部主体阶段通过后评估 S5。

## 技术边界

- 保留 `ShipDimensionEffects` 的 `SkyType.NONE` 和 `PlanetRenderer` 的统一入口。
- 保留 `SpaceRenderContext`、真实宇宙坐标、稳定相机姿态及现有转向/跃迁时钟。
- 星系间距通过平移完整星系调整，禁止分别手工移动同一星系的恒星、行星与停靠点。
- 保留现有 4K 行星颜色贴图，不以继续提高分辨率代替材质、光照和动态层次优化。
- 行星自转不得通过逐帧重建全部球体 VBO 实现，也不得让烘焙明暗面随地表一起旋转。
- 保留 `StellarLodPolicy` 的 3 颗完整恒星与 16 颗简化恒星预算，除非性能数据证明需要调整。
- 新增背景几何和恒星球体应缓存为共享 VBO；禁止每帧重建纹理、噪声数组或大型集合。
- 新效果必须恢复 OpenGL 渲染状态，不能污染方块、实体、透明材质或后续 HUD 的绘制。
- 任何视觉配置只作用于客户端，不改变服务端飞船位置、航行阶段和燃料结算。

## 验证清单

每个阶段至少检查：

- 停靠于现有不同天体时，行星、恒星和背景遮挡顺序正确；
- 第一星系观察第二星系时具备明确远景感，跨越中间区域时存在足够长的无主导星系深空段；
- 四类行星的光照、大气和材质效果符合各自类型，自转时明暗面不会随贴图错误旋转；
- 两个已有恒星系与深空过渡位置的颜色和密度连续；
- 第一人称站立、行走、转头和开启/关闭视角晃动时，远景天体不抖动；
- 亚光速短航线与超空间长航线不会混用视觉效果；
- 调整窗口尺寸、FOV、GUI Scale 和渲染距离后无接缝、裁切或整屏过曝；
- 首次进入飞船维度与重复进入后无明显新增卡顿；
- 普通场景和最多 3 颗 `FULL` 恒星同时可见时无持续性能退化；
- 客户端视觉确认前不提交最终美术参数。

## 当前结论

第二星系已经整体移动到更合理的远方，当前应先完成客户端距离感确认，再开始 S0 深空层次，让世界
尺度与背景表现拥有一致的距离逻辑；随后在 S2 中利用现有高分辨率贴图改善行星光照、大气、材质和缓慢自转。
近距离恒星可以采用同类球体技术，但必须保留“恒星自发光”这一视觉逻辑，并且只替换 `FULL` LOD
的核心。尺度、背景、行星与恒星分开验收，才能准确判断视觉问题来自哪一层。
