## 1. 本次规则调整

用户要求将“识别背包钻石并扣除修复”改为“打印亚光速引擎点火核心，放入飞船引擎维修模块槽”。
飞船引擎定位为初始船载设备；用户明确本轮先做创造模式调试，不新增引擎制作配方、不修改初始飞船模板。

| 项目 | 当前实现 |
| --- | --- |
| 引擎方块 | 新增 `starboundmc:ship_engine_unit`，独立模型、6 张原创像素贴图与反应室动画；承载原维修槽和界面 |
| 推进器 | 历史 ID `starboundmc:ship_engine` 保持不变，显示名改为“飞船推进器”；移除维修入口，原模型保留 |
| 点火核心 | 新物品 `starboundmc:sublight_ignition_core`，创造模式物品栏可取 |
| 核心配方 | 暂采用建议值：3 钻石 + 50 体素，打印 5 秒，产出 1 核心；数值仍可按反馈调整 |
| 维修入口 | 飞船维度内，右键飞船引擎，将核心放入唯一维修模块槽，自动安装 |
| 个人条件 | 安装者背包或副手持有采矿等级 ≥1 的物质枪，升级仍互相独立 |
| 共享条件 | 核心已重启、首次登陆完成、矿物扫描完成，亚光速引擎仍损坏 |
| 消耗与点火 | 只消耗槽内 1 核心，服务端 60 tick 点火，共享修复结果 |
| 后续模块 | `engine_repair_modules` 物品标签定义槽位接收范围；当前仅点火核心有处理逻辑 |
| 超光速 | 显示现有共享状态，尚未实现维修模块、配方或修复操作 |
| AI 终端 | 查看升级、打印和安装指引；旧维修动作 ID 4 保留解码但服务端不执行 |

此前确认的工作台配方保持：4 铁锭 + 1 红石 + 1 工作台 + 50 体素，打印 5 秒。
物质枪升级模块仍为 1 青金石 + 4 铁锭 + 100 体素，5 秒产出 2 个。
不追踪钻石的获取来源；打印继续复用现有个人钱包、材料预留、打印队列与输出槽。

## 2. 玩家路线与调试入口

```text
核心重启 → 首次登陆 → 矿物扫描
  → 打印升级工作台和升级模块
  → 自己的物质枪采矿等级提升至 1
  → 收集钻石与体素，在打印站制作点火核心
  → 打开飞船引擎，放入核心
  → 自动消耗 1 核心，约 3 秒点火
  → 共享亚光速引擎上线，加燃料后可同星系航行
```

本轮调试：在飞船维度用创造模式取得并放置“飞船引擎”，取得“亚光速引擎点火核心”，
右键打开界面。创造模式不跳过剧情和工具校验；需要先完成前置流程。
普通世界放置时显示“未连接飞船”，物品保留。
引擎无需合成；新引擎由玩家从创造物品栏手动放置。已有模板中的旧方块是推进器，保留原位置与外观。
原推进器在上一版保存的模块可通过右键取回（满背包时掉落），不打开维修 UI，也不接受漏斗插入模块。

物品不足、剧情未完成或工具等级不足时，槽内核心保留，可取回。
成功安装后，关闭界面、玩家离线或拆除引擎不会中断已开始的共享点火。
已上线引擎不再消耗核心。引擎内未使用的物品在拆除时掉落。

## 3. 服务端和存档边界

- 原版容器负责唯一机器槽及 36 个玩家槽，共 37 个；普通拖放和 Shift 点击共用同一库存。
- 服务端在原版槽位事务结束后的菜单同步阶段尝试安装；复核当前菜单绑定、方块、
  飞船维度、玩家距离、旁观者状态、个人工具和共享进度。
- `beginSublightIgnition` 是全船一次性接受条件；多个玩家或多个引擎顺序处理时，
  仅首次成功转换状态的操作消耗一个核心。
- 玩家库存不再扫描或扣除钻石；钻石只作为数据驱动打印配方材料。
- 槽内物品使用方块实体 NBT 保存，点火截止时间继续使用 schema 3 的共享 `ShipStateData`。
- 原推进器继续支持旧方块实体 NBT，仅用于保存和归还旧调试槽物品。新引擎使用同一存储类型，
  但菜单有效性、维修服务和漏斗插入均验证新的方块 ID；旧推进器不能触发点火。
- 老世界无 Story 时保留原有解锁迁移；已修好亚光速或双引擎的存档不回退。
  未来 schema 保持只读，不接受安装。
- 正常保存再加载保持槽位剩余数量及点火截止时间。强制杀进程导致两个存储未同时落盘，
  不属于本轮承诺的跨文件事务保障。
