# 舰载机器 UI 优化 — Design Contract / 工作记录

2026-09-22。依据用户指令“针对其它机器的 UI 进行优化/美化，允许在合理范围内调整页面逻辑”。
使用已认可的[石墨舰载制造终端语言](../ui-fabrication-style.md)，按设备用途形成差异。
本轮允许调整说明、焦点、按钮状态与页面内阅读顺序；槽位、配方、权限、网络与存档语义保持稳定。

## 总体约束

- PURPOSE：更容易判断设备能做什么、当前状态及下一步动作。
- INTERACTION FANTASY：操作飞船内真实的加工、维护、补给和导航设备。
- SCREEN MODE：普通机器为 Utility；传送器、引擎、升级台、AI 为 Feature。
- PRIMARY VISUAL：每台设备各自的工作对象或关键状态，见下表；不套统一三栏布局。
- ART / CUSTOM VISUALS：石墨外壳、内凹槽位、凸起按键、硬像素符号；沿用已有设备专属画面。
- GENERIC UI：平铺列表、按钮、输入、背包槽、滚动条和提示共享状态语言。
- MOTION / FEEDBACK：只显示工作进度、选中、焦点和状态变化；没有新增待机装饰动效。
- STATES：默认、悬停、按下、选中、禁用、短缺、工作中、完成；禁用必须解释原因。
- DO NOT：不改打印站已认可外观；不将所有机器变成青色；不添加逐行卡片或冗余仪表板。
- IMPLEMENTATION CONTRACT：服务器继续拥有数据和槽位；皮肤绘制无额外命中；保持原版背包交互。

## 页面概念与验收范围

| 页面 | 主体 / 信息优先级 | 操作流程与空间组织 | 重点改进 |
| --- | --- | --- | --- |
| 燃料控制器 | 琥珀储量 → 可补充燃料 → 补充操作 → 背包 | 上部储量、燃料槽和操作，下部背包 | 燃料条统一琥珀语义；去套框；满油与无有效燃料提示 |
| 体素提炼机 | 输入到产出的青色处理通道 → 待领取量 → 开始/停止 | 保留输入左、输出右及下方操作与背包 | 压低边框层级；中性余额；明确可领取与处理状态 |
| 合金炉 | 输入/燃料到产出的熔炼通道 → 进度 → 背包 | 保留已有三个机器槽位和背包坐标 | 替换旧绘制，琥珀热源与青色工艺进度，显示状态及完整提示 |
| 飞船货箱 | 货物网格 → 容量 → 玩家背包 | 保留 54 格货物和原有背包分区 | 石墨母主题，去嵌套框，货物区与玩家区用间距区分 |
| 传送器 | 目的地选择 → 可达性 → 传送操作 → 命名 | 保留紧凑导航与命名流程 | 白/青导航主题，列表选中与禁用区别，输入和滚动皮肤 |
| 飞船引擎 | 反应堆/核心 → 故障与修复状态 → 下一步 | 保留专属反应堆视图和核心槽 | 标题与编号不重叠，状态文字可读，槽位与提示一致 |
| EPP 维护站 | 当前装备 → 可执行维护 → 原因 → 背包 | 保留装备、模块、升级套件三个槽与对应操作 | 明确禁用原因与安全环境，控件状态和字体一致 |
| 生命维持站 | 补给对象 → 氧气/充装状态 → 操作 | 沿用装备与补给流程 | 检查密度、动作可发现性、消耗与禁用反馈 |
| 物质枪升级台 | 枪体蓝图 → 子系统 → 成本与升级 | 保留已批准的工程蓝图及节点关系 | 局部控件、槽位、提示精修，不重做构图 |
| N.O.V.A. 终端 | 全息形象 → 当前任务/状态 → 操作 | 保留现有终端页面与任务流程 | 检查文字和共用控件的一致性，保持全息身份 |

星图属于空间体验界面，个人装备屏属于背包功能，不进行机器皮肤替换；废弃旧控制台仅保留兼容。

## 最终实施边界

- `MachineUiSkin` 仅为主动接入的机器提供 1px 边缘、槽位内凹和滚动箭头，不决定填色和页面结构。
- `ShipboardTooltipStyle` 通过根节点 `shipboard-machine` 标记接入；原版背包、个人装备屏、HUD 和打印站没有被这条公共路径覆盖。
- 燃料为琥珀储量、体素为青色进度，货箱为中性石墨。去除基础设备的嵌套描边；清理公共 LSS 中已经不被打印站使用的旧规则。
- 燃料按钮按实际可容纳的完整物品计算是否可用，保留服务端按槽顺序、遇到首个放不下的物品即停止的语义。
- 提炼机的状态、领取区与开始/停止按钮不再重叠，领取区与输入槽对齐，物品图标保持 16px。
- 合金炉改用 LDLib2 生命周期，面板仍为 176×176；槽位装饰直接读取 Menu 的坐标。39 槽顺序仍为输入、燃料、输出、27 格背包、9 格快捷栏；配方和 quick-move 未修改。
- 传送器为 184×204，命名框和保存键上下排列；服务器快照不会覆盖未保存草稿，初次显示名称从开头开始。未选择目的地时不占用空图标空间。
- 引擎缩窄标题占位，保持反应堆、核心槽及点火表现；动态状态的完整提示随文字更新。
- EPP 维护使用各操作的条件提示；不安全环境以琥珀文字说明。生命维持站保留自动补给流程并显示充装条。
- 物质枪保留绿色枪体蓝图和节点关系，只改壳体、背包槽和文字裁切。N.O.V.A. 保留全息、四页导航及对话；禁用主操作仍保留按钮外形，滚动箭头和多行提示统一。

## 验证方法及实测范围

实机检查使用独立的 `run-ui-review/` 运行目录及存档副本。临时渲染夹具位于忽略的 `build/ui-review-src/`，由专用 Gradle init script 挂入；普通构建不包含该夹具。
截图使用真实 Minecraft + NeoForge + LDLib2 渲染，测试数据仅用于客户端显示，不发送机器操作请求。

- 第一轮：10 个页面 × 中英文 × GUI Scale 2/3/4，1440×1080 窗口，共 60 张截图。
- 第二轮：中英文 Scale 3 共 20 张，覆盖满油禁用、提炼运行/停止、维护环境不安全、生命维持供气不足、传送器选择、N.O.V.A. 已同步对话。
- 传送器通过真实 TextField 注入未保存草稿，再触发收到新命名快照，断言草稿仍保留；两种语言均记录 `UI_REVIEW_DRAFT_PRESERVED`。
- 首轮发现英文空选择说明被占位图标挤窄，已修正；末轮中英文 Scale 3 共 6 张，复核名称开头显示、提炼物品图标及升级台标题。
- 截图保存在 `run-ui-review/screenshots/`；运行日志分别为 `build/ui-review-run.log`、`build/ui-review-states.log`、`build/ui-review-final.log`。
- 新增 `FuelPreviewTest`：完整物品、容量边界、槽位顺序阻塞、空/无效燃料，以及 0–1000 油量下与逐个消费算法的一致性。

本轮验证证明界面渲染、显示状态及命名草稿更新行为；不将渲染夹具当成真实服务器的制造、领取、维护或传送交易验证。多人同步、完整拖拽/双击/快捷交换及服务端失效回归仍沿用各功能计划的独立验收范围。

最终普通构建已排除临时渲染夹具；通过 JAR 内容检查。10 页截图预览索引位于 `build/machine-ui-preview.md`。
