## 文档目的

引入模组通用货币与基础构成单位“体素”，并提供两台配套机器：把材料提炼为体素的**体素
提炼机**，以及以“基础材料 + 体素”打印复杂科技制品的**体素打印站**。本文只记录已确认
需求、实现边界、技术要点和阶段划分；尚未确认的设定不得在实现时自行补全。

## 背景与设定

- **体素（Voxel）** 是本模组中物质的基础构成单位，同时也是一般交易货币。它既是“钱”，
  也是“材料”：复杂制品在设定上就是大量体素按结构聚合的产物。
- **体素提炼机** 承担“物质 → 体素”的还原：投入矿物等基础材料，按其密度提炼出体素。
- **体素打印站** 承担“体素 → 制品”的重组：投入基础材料作为结构骨架、消耗足量体素作为
  填充物质，快速打印出复杂科技制品。**形态参考《深海迷航》（Subnautica）制造机
  （Fabricator）的壁挂式 3D 打印机**：贴墙放置的薄机身，左右各一个激光探头，打印时
  双探头左右交替把激光打在成型物品上，物品自下而上逐渐完整。
- 首发打印制品为**物质枪升级模块**，目标是形成“采集材料 → 提炼体素 → 打印模块 → 升级
  物质枪”的核心循环。模块当前的工作台配方（钛锭 + 星核碎片 + 耐钢锭 + 红石 → 2 个）是
  早期分支添加的**临时配方**，已确认在 M3 落地打印配方时移除，模块改由打印站独家产出。
- 现实约束：钨、钛、耐钢、星核矿石尚未加入自然世界生成（见根 README 的 Alpha 限制），
  且首版分解数值**只覆盖原版物品**；模组本体矿物的体素数值待其世界生成接入后再按同一
  密度规则补充。验收期间材料以创造/管理员补给为主，不影响系统按生存规则实现。

## 首版实现边界

首版目标是打通“提炼体素 → 点击领取到钱包 → 打印扣钱包 → 制品产出”的完整闭环，只实现：

- 体素物品与玩家体素钱包（数据附件持久化、拾取自动存入、右键使用存入、余额 HUD）；
- 体素提炼机、体素打印站两个方块（含方块实体、菜单与 LDLib2 界面）；
- 提炼完成后的体素在机器公共输出缓冲中暂存显示，任意玩家点击体素图标后一次性存入
  点击者钱包（先点击者获得）；打印直接扣除打开者钱包余额（两台机器均无可存取的站点账户）；
- 两条数据驱动配方线：分解配方（物品 → 体素，由提炼机使用）与打印配方（材料 + 体素
  → 制品，由打印站使用）；
- 生物死亡掉落体素物品（普通生物 5、怪物 20），玩家拾取时自动存入钱包；
- 仅打印站写入初始飞船模板（新存档开局自带）；提炼机由玩家合成获得；
- 首批打印配方：物质枪升级模块；
- 中英文本地化与创造模式物品栏条目。

## 已确认决策

- 货币名称：中文“体素”，英文 Voxel，物品注册 ID `voxel`。
- 形态（2026-08-31 修订）：**玩家钱包为主、物品为辅**——每个玩家持有随存档持久化的
  体素钱包；体素物品被拾取时自动全额存入钱包，手持右键使用亦存入钱包；**不做钱包
  提现**（体素物品仅通过创造模式或未来功能出现）。未来可考虑加入体素压缩机，把钱包
  余额按 K/M 压缩为物品形态存储（远期设想，不纳入本计划）。
- **机器拆分**：提炼与打印是两台独立机器。提炼机只做“材料 → 待领取体素 → 玩家钱包”，
  打印站只做“材料 + 体素 → 制品”（直接扣打开者钱包）；打印站不承担分解职能，两机均
  不设玩家可存取的站点账户。
- 体素获取途径（首版两条）：
  1. 体素提炼机分解材料（首版仅原版物品，完成后点击体素图标领取到钱包）；
  2. 生物死亡掉落体素物品（普通生物 5、怪物 20），地面掉落、玩家拾取时自动入钱包。
- **分解定值规则**：以现实物质密度近似折算，密度越大产出体素越多；同元素物品同值
  （钻石与煤炭同为碳，故同级）。基准：煤炭 5。首版数值表见“功能需求”。
- 打印行为：**耗时打印**——服务端权威计时，典型时长数秒（参考深海迷航制造机节奏），
  界面显示进度并配全息预览与成型动画；不消耗能量，不与燃料体系联动。
- 配方载体：**JSON 数据驱动**——新增本模组自定义配方类型，配方文件置于
  `data/starboundmc/recipe/`，支持数据包扩展。
- 首发制品：物质枪升级模块（现有 `matter_manipulator_module` 物品，不新增模块物品）。
- 模块现用工作台配方为临时配方：M3 落地模块打印配方时删除
  `data/starboundmc/recipe/matter_manipulator_module.json`，模块改由打印站独家产出；
  打印站初始飞船自带，开局即可用，不构成进度卡点。
- 机器获取（2026-08-31 修订）：**仅打印站写入初始飞船模板**（左舷舱壁，贴墙），新玩家开局
  即可使用；**提炼机不随飞船生成，由玩家制作获取**（原版材料合成，作为中期进度目标，
  配方数值待复核）。

## 功能需求

### 体素物品

- 注册 ID `voxel`；中文名“体素”，英文名 Voxel；加入创造模式物品栏。
- 堆叠上限 99（原版硬上限：MAX_STACK_SIZE 组件与创造模式槽位网络包均封顶 99，
  超过即断连，故 999 不可行）；tooltip 说明其“物质基础构成单位 + 通用货币”设定。
- **贴图（M0 定稿）**：黄色小立方体，立方体对角线视角（等距/斜二测，可见三个面）；
  光源设定在左侧，三个面明暗各不相同——受光的左侧面最亮，顶面居中，背光的右侧面
  最暗；具体色阶实现时给用户预览确认。像素画风格与现有物品贴图一致。
- 拾取自动入钱包：地面上的体素物品被玩家拾取时不进背包，直接全额存入钱包（配经验球
  式拾取音效与音调扰动）；手持体素物品右键使用同样全额存入钱包。

### 体素钱包

- 每玩家独立余额，使用 NeoForge 数据附件（`starboundmc:voxel_wallet`）随玩家数据
  持久化，死亡不丢失（copyOnDeath）。
- 余额变动由服务端权威执行并即时同步客户端；余额为非负整数，上限 Integer.MAX_VALUE。
- 余额显示：仅在玩家背包界面右下角以小字显示（如“体素：12,345”），不做常驻 HUD。
- 提炼领取后存入钱包，打印直接从打开者钱包扣除；钱包仍是玩家持有体素的唯一账户，
  提炼机右侧数量只表示机器公共待领取结果，不绑定玩家，也不提供存款、提现或实体体素输出。

### 体素获取：提炼机分解

- 分解定值规则：密度越大体素越多，同元素同值。首版数值表（仅原版物品，M3 前可由
  用户复核调整）：

  | 物品 | 体素/件 | 依据 |
  | --- | ---: | --- |
  | 煤炭 / 木炭 | 5 | 碳，基准值 |
  | 钻石 | 5 | 同为碳，与煤炭同级 |
  | 红石粉 | 3 | 虚构矿物粉末，低密度 |
  | 青金石 | 4 | 青金石矿 2.4 |
  | 绿宝石 | 5 | 绿柱石 2.7 |
  | 粗铁 / 铁锭 | 15 | 铁 7.87 |
  | 粗铜 / 铜锭 | 17 | 铜 8.96，密度略高于铁 |
  | 粗金 / 金锭 | 40 | 金 19.3 |
  | 远古残骸 | 30 | 虚构高密度残骸 |
  | 下界合金锭 | 50 | 虚构超密合金 |

- 粗矿与锭同值（熔炼无损，分解亦无损）；矿石方块暂不参与分解。
- 模组矿物（钨、钛、耐钢、星核）待世界生成接入后按同一规则补表。
- 提炼耗时约 1–2 秒/件；M0–M5 保持单次提炼一件。M6 改为**手动启动的连续批量提炼**：
  放入物品后保持待机，只有点击“开始提炼”才启动；开始后只要输入槽仍有匹配配方的物品，
  就按“一件一个周期”串行处理整栈，不缩短单件耗时，也不并行处理。运行时同一按钮变为
  “停止提炼”；点击后立即取消当前未完成周期并恢复为“开始提炼”，本件物品不消耗、也不产出
  体素。玩家仍可随时取出全部或部分输入来停止，剩余输入保持待机。已完成产出累计到同一公共
  输出，停止或材料耗尽后统一领取；不提供单次/连续模式切换。

### 体素获取：生物掉落

- 普通生物（被动）死亡掉落 5 体素，怪物（敌对）死亡掉落 20 体素；固定必掉，不受
  抢夺影响（首版），排除玩家。
- 实现优先数据驱动（战利品表注入或全局战利品修改器）。
- M5 数值复核（2026-09-01）：当前模块的 100 体素成本等于 5 只敌对生物、20 只被动生物、
  2.5 个金锭或约 6.7 个铁锭的提炼产出，且另需 1 青金石和 4 铁锭。为保证 Alpha 核心循环
  易于验证，首版保留 5/20 掉落和既定分解表；刷怪塔的规模化收益列为长期实测项，不视为
  最终经济平衡。

### 体素提炼机

- 注册 ID `voxel_refinery`；可放置、可破坏、带战利品表；朝向与外观在实现阶段设计，
  视觉语言与打印站同族。
- 结构与方向固定为：**左侧材料输入槽 → 中间进度箭头 → 右侧体素图标与体素数量**。箭头
  在提炼期间表现进度和方向，不能让玩家误认为左右两侧都是普通物品槽。
- 放入匹配分解配方的物品并启动后，约 1–2 秒销毁一件物品；产出的体素先写入机器的
  公共“待领取体素”状态。右侧显示体素图标和待领取数量，完成后图标亮起并成为明确的
  点击目标；任意玩家点击后，服务端把当前显示的全部数量一次性存入点击者钱包并原子清零，
  先完成有效点击者获得该笔体素。
- 右侧体素图标是领取按钮，不是物品槽，不生成或取出实体体素物品。无待领取体素、机器
  仍在运行时图标不可领取，并以禁用状态和 tooltip 说明原因。
- 空闲且左侧有有效材料时，右侧可预览本次预计体素数量；运行中由箭头显示进度；完成后
  数量切换为实际待领取值。所有查看者看到同一份服务端待领取数量，界面显示值必须与服务端
  当前可领取值一致；某位玩家领取后立即向其他查看者同步清零。M0–M5 在上一笔结果领取前
  不启动下一笔，避免覆盖待领取数量。
- 关闭界面、玩家离开不中断提炼；方块实体只持久化待领取体素数量，不持久化领取者 UUID；
  任何玩家重新打开后均可领取。破坏时输入槽物品掉落，未领取的公共体素转换为体素物品掉落，
  不建立或恢复玩家 UUID 归属。

### 体素打印站

- 注册 ID `voxel_printing_station`；可放置、可破坏、带战利品表。
- **壁挂式方块**：贴墙放置（四向水平墙面，放置时面向玩家），薄机身不占房间地面空间；
  严格 1 格宽，模型限制在一格（16×16×16）内，不做视觉越界或多方块结构；附着墙被
  破坏时打印站一并掉落（同原版壁挂方块行为）。
- 外形：白色系圆角科幻机身，正面中央为成型腔/观察窗，左右各一个常驻可见的激光探头
  （小凸起造型，非打印时暗淡待机，打印时点亮）；具体造型与配色在 M1 出占位、M4 定稿。
- 方块实体管理：材料输入槽、产物输出槽、当前打印任务状态。
- 体素来源：**打印直接扣除打开者的体素钱包**（服务端校验余额并扣款、同步）；
  站内不设体素槽或站点账户。
- 打印流程（服务端权威）：
  1. 玩家在界面选择配方；
  2. 服务端校验材料槽内容与打开者钱包余额，不足则拒绝并提示具体原因；
  3. 校验通过后立即扣除材料与钱包体素，开始计时任务（典型 3–6 秒，随体素成本小幅
     缩放，模块定稿 5 秒）；中途打开者离开不停止计时，扣款已完成故不受影响；
  4. 任务完成后产物进入输出槽；输出槽被占用时保持完成状态等待取出；
  5. 关闭界面、玩家离开不中断任务；M0–M5 同一时间每站只运行一个任务，不做队列。
- M6 正式加入**打印队列与重复打印**：玩家在右侧物品详情中调整合成个数，再把对应重复
  次数加入队列；打印站仍只串行执行一个当前任务，完成后按顺序启动下一项，不做多任务并行。
  界面显示当前项及其打印进度百分比、后续顺序、请求者和取消入口。M6 规则于 2026-09-01 定稿：单次调整范围
  1–64，提供 ±1 与 ±10 快捷按钮；增加数量时按当前材料可制作次数和整机剩余队列容量自动
  钳制，到达上限后禁用继续增加。整台机器最多保留 64 次未交付打印；严格 FIFO；入队时一次性预扣全部材料和请求者
  钱包体素，玩家离线后仍继续；队列公开可见，只有请求者能取消自己尚未开始的队列项；
  取消时体素退回请求者钱包、材料退回其背包，背包满则掉落脚下；当前任务不可取消；输出
  阻塞时整个队列暂停，不跳过任务。
- 打印站是公共机器：任何打开者均可使用（消耗各自的钱包），Alpha 不做权限分级。
- 破坏时输入/输出槽物品正常掉落；已经完成但仍等待输出的当前结果直接作为结果物品掉落；
  尚未完成的当前项及队列项取消，其预扣材料和体素均转换为物品在机器处掉落。因请求者可能
  已离线，拆机退款不直接写回玩家钱包或背包。

### 配方体系

- 分解配方类型（建议 `voxel_decomposition`）：物品 → 体素数量，由提炼机使用。
- 打印配方类型（建议 `voxel_printing`）：材料条目（物品 + 数量，种类数上限与材料槽
  位数一致）、体素成本、打印时长、产物，由打印站使用。
- 首批配方：上表原版分解配方（14 条 JSON 已落地）+ 物质枪升级模块打印配方
  （1 青金石 + 4 铁锭 + 100 体素 → 2 模块，5 秒，已落地）。

### 界面与视觉

- 遵循《普通机器界面 LDLib2 迁移计划》的机器界面边界：紧凑、信息密度接近旧机器界面、
  两机共用视觉家族但不做大型控制台，不纳入星图视觉体系。
- 打印站界面（M4 定稿）采用固定的**左侧配方列表 + 右侧物品详情**结构：
  - 顶部显示打开者钱包余额（只读），材料槽、输出槽与当前打印进度保持可见；右侧队列中正在
    打印的物品同时显示百分比，完成但因输出阻塞等待交付时保持为 100%；
  - 左侧使用可滚动列表展示全部打印配方，不改用网格。每行至少显示成品图标、名称与单次
    产出数量；当前材料和钱包体素均满足要求的配方亮起，不满足的配方降亮度显示；
  - 不满足条件的配方仍可选中查看详情，不能只隐藏。悬停或详情区必须给出具体禁用原因，
    并区分材料不足、体素不足、输出受阻和机器忙碌；选中状态与“可打印”亮起状态分别表达；
  - 右侧显示选中成品的大图/名称、单次产出数量、所需材料及“当前/需要”数量、体素成本、
    单次耗时、当前合成个数、总产出和总消耗；M0–M5 合成个数固定为 1，M6 开放 ±1/±10
    数量调整，并按材料与队列容量限制最大可选次数，再将对应重复次数加入串行打印队列；
  - 选中配方只更新右侧详情，不消耗资源。M0–M5 点击“打印”后启动单次任务；M6 点击
    “加入队列”后按所选合成个数创建队列项。按钮状态和提示只负责易用性，服务端仍需重新校验。
- 打印过程视觉参考深海迷航（Subnautica）制造机（Fabricator），三段式成型流程
  （M4 定稿）：
  1. **即时响应**：点击“打印”或“加入队列”且服务端确认资源满足后立即响应，无二次确认
     或预热等待；仅在列表中选中配方不会直接消耗资源；
  2. **全息预览**：成型腔内浮现成品的半透明青/蓝白色全息影像，给出“要造什么”的预期；
  3. **双探头逐层成型**：左右两个激光探头**左右交替**发射激光，打在成型物品当前的
     成型高度上（光点可沿成型线小幅度扫描），实体部分**自下而上逐层替换**全息影像，
     成型线随进度上移；完成瞬间光效收敛，实物定格；
  4. **交付**：成品进入输出槽，由玩家在界面取出。
  与深海迷航的差异（有意保留）：资源与交付语义——深海迷航直接扣玩家背包、成品回
  背包，本模组扣站点材料槽与玩家体素钱包、成品入输出槽（服务端权威、离线继续工作、
  多人共享需要）。实现层面借鉴其壁挂形态、节奏与视觉语言，不逐帧复刻；本模组不
  打包音频，首版不配自定义音效。
- 打印动画由方块实体渲染器（BER）实现：双探头激光束、全息影像与逐层实体化均需
  服务端进度同步驱动；项目已有 `LaserRenderer`（物质枪激光）等先例。
- 提炼机界面（M4 定稿）从简并保持清楚的单向流程：左侧为被提炼物品槽，中间为指向右侧
  的进度箭头，右侧为体素图标与数量；点击亮起的体素图标领取全部待领取体素。界面同时
  显示当前钱包余额、预计/待领取数量、进度和不可领取原因，中英文及常用 GUI Scale 下均
  保证体素图标具有足够点击面积。
- 使用 `StarboundModularScreen` 生命周期桥与独立 LSS 样式；支持中英文与常用 GUI Scale。

## M0–M5 非目标

- 不做钱包提现（钱包余额无法转回体素物品）；体素压缩机等“余额→物品”方案仅作远期
  设想，不在本计划范围内。
- 不做交易系统、NPC 商店或任何“体素买东西”玩法。
- 不引入能量/电力体系，提炼与打印均不消耗飞船燃料。
- 不做物质枪采集副产体素（明确推迟，未来可复议）。
- 不做任意方块 → 体素的完整物质分解；分解只认配方，且首版不含模组矿物与矿石方块。
- M0–M5 不做打印队列、批量打印或提炼机连续批量提炼；这些能力已排入 M6。M6 仍不做
  多任务并行，提炼与打印都保持服务端权威的串行状态机。
- 打印站不做分解职能；两机均不做站点体素账户。
- 不做站点权限分级（钱包天然按打开者区分）。
- 不修改服务端跃迁、燃料、传送与剧情业务；不改动现有注册 ID 与菜单语义。

## 技术要点

- 注册：`ModBlocks` / `ModBlockEntities` / `ModItems` / `ModMenus` 扩展（两个方块、
  两个方块实体、两个菜单）；注册 ID 需通过 `Stage1RegistrationIdsTest` 一致性检查。
- **新增 Java 源文件必须同步加入 `build.gradle` 中 `src/main/java` 与测试源集的
  `include` 白名单**，否则不参与编译与测试。
- 网络：沿用 payload 协议（`ModNetwork`）。新增 playToServer 包：开始打印、开始提炼；
  新增 playToClient 包：任务与提炼进度同步（钱包余额同步 `SyncVoxelWalletPacket`
  已随 M0 落地）。服务端动作接入 `ServerPayloadActions` 分层（新增 Stage 层或并入
  现有层，实现时定）。
- 持久化：钱包余额存玩家数据附件（M0 已落地：`voxel_wallet`，copyOnDeath）；机器
  任务状态存方块实体数据；不引入全局 SavedData。
- **壁挂方块实现**：打印站为贴墙方块（水平四向 FACING，放置时面向玩家；附着墙失效
  时自行掉落，参照原版壁挂方块如按钮/压力板的支撑检查机制）；碰撞箱为贴墙薄盒。
- **打印动画渲染**：方块实体渲染器（BER）负责双探头激光束、成品全息影像与自下而上
  逐层实体化；打印进度需由服务端同步到客户端（方块实体数据同步或既有 payload 通道），
  参照 `LaserRenderer`（物质枪激光）先例。
- 配方：新增两个 `RecipeType` 与序列化器；配方 JSON 随模组发布并纳入资源完整性测试
  （`Stage10ResourcesTest` 模式）；是否提供 datagen Provider 在 M3 决定。
- 飞船模板：修改 `ShipStructure` / `ShipTemplatePlacer` 仅放置打印站（左舷舱壁，需预留
  一面合适的舱内墙面），并同步 `StarterShipHullProfile` 相关测试；提炼机不进模板。
- 测试：注册 ID、payload 编解码、钱包数值与编解码、提炼与打印状态机（材料/体素不足
  拒绝、破坏中断、输出占用）、配方 JSON 加载、生物掉落；用户视觉与交互验收通过后才
  可合并。
